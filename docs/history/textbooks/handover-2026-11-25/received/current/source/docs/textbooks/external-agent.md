# External textbook continuation

Use this guide when starting or recovering an external textbook agent. The seed's
`STATE.json` pins the accepted published repository commit and lists any additional
unreceived files. That state replaces older checkpoint startup instructions.
Read the restored repository's [AGENTS.md](../../AGENTS.md) before implementation.

## Resume

1. Verify the supplied archive's recorded hash and complete member inventory.
   Restore its exact public Git prerequisite and apply every declared update and
   deletion. Compare the resulting tree with the recorded tree. An accepted seed
   with no unreceived work needs only that repository checkout and its operational
   files; no preceding checkpoint or private donor objects are required.
2. Read [CTB.json](CTB.json), [coverage.json](coverage.json) and the
   [inbox](inbox/README.md). Follow their pointers to the complete canonical book,
   chapter and appendix requirements before choosing a bounded obligation.
   The selected next task is not the complete remaining programme.
3. Reuse a matching environment. Follow the repository's development instructions;
   if Nix is unavailable, the seed's separately identified native adapter and
   setup guide retain the authorized route with the same compiler/dependency pins.
   Downloads, installations, dependency caches and build outputs stay external.
4. Continue the selected mathematical obligation with connected examples and
   independent Standards and Spec review. Keep Astra as instructed by the user;
   capacity delays do not authorize a model change. Record actual validation
   outcomes against exact candidates. A historical remote check with an unknown
   outcome does not prevent a new check in an independently owned workspace.

On interruption, inspect the current checkout and the commands owned by this
session before resuming. Preserve intentional edits and useful logs. Check for
surviving writers before restarting a check in the same workspace. Recovery of
an old conversation or execution handle is unnecessary once the complete state
has been restored and the new workspace is independently owned.

The external author prepares deliveries on its own branch and leaves receiving
`master` publication to the conaled integration agent. Local authoring may continue
while a frozen delivery is being received. Track subsequent work separately and
keep it in the next delivery until receiving acceptance is confirmed. Follow the
user's actual communication authorization; a ticket reference grants none.

## Mathematical records

Use book-qualified obligation names, defined in the
[obligation crosswalk](obligation-names.json). For example, `FDSA-5-85` means
Chapter 5 ledger row 85; it does not assert that the printed book has an exercise
numbered 85. Historical `C05-085` refers to the same row. Preserve literal
historical requirements and source references. CTB task IDs and GitHub issue
numbers are different namespaces and retain their existing meanings.

Keep the complete source, examples and paper mathematics in ordinary repository
owners. Put useful incomplete arguments in a maintained preparation paper and
link it from the inbox. Record hypotheses, counterexamples, source-reading limits
and the exact gap to the canonical requirement. An unfinished proof plan belongs
with the mathematics, even if first written in a directory named `evidence`.

CTB owns task progress; coverage owns qualified obligations and denominators;
GitHub owns receiving work and shared-library follow-ups. Qualification requires
matching checks and independent review of the intended mathematical claim.
Partial constructions remain useful without qualifying the complete obligation.
Distinguish declared source-work tariffs from allocation, bit cost or machine time.

## Save the complete unreceived state

Check for useful unsecured work at least every thirty minutes, after a substantial
batch and before a context transition. Save recovery material even while checking
or review is incomplete. Record those limitations; they are not a reason to leave
new mathematics dependent on the conversation.

Each delivery declares:

- The exact accepted published Git prerequisite and resulting source tree.
- Complete changed/new file bodies and explicit deletions relative to that
  prerequisite, including uncommitted work, useful paper drafts and current
  requirements. Account for useful work on other local branches before pruning.
- One concise current state: active work, unfinished obligations, unresolved
  review findings, validation identities/outcomes and next action. Refer to
  accepted repository owners instead of copying them into the archive.
- A complete path, size, mode and SHA-256 inventory, plus the restoration procedure
  and any external compiler/dependency requirements.

Rebase against a newer receiving commit only after reconciling its changes and
verifying every unreceived result survives. Then recompute the complete delta
against that commit. Advancing the prerequisite alone can silently lose work.
The delivery must restore with no earlier checkpoint and no private Git objects;
verify that in a fresh destination before describing it as self-contained.

Use dated, consecutive filenames with distinct delivery identities. Keep older
archives separately. The uncompressed selected-payload limit is 512 MiB
(536,870,912 bytes), following the user's 22 November 2026 override. Report both
the uncompressed payload and the actual uploaded archive size; the compressed
delivery size is the user's primary concern. Exclude nested archives, installed
tools, caches, build outputs, downloads, incomplete transfers and repeated
operational history.
Keep reusable environment adapter sources separate from mathematical payloads.
Recompute any removal disposition against the actual immediate predecessor;
retire processed material only after verifying its surviving mathematical owner.
Keep one complete current source body and the useful mathematical preparation,
fixed requirements, review records and evidence needed for current acceptance.
Retire duplicate copies, superseded mechanical receipts and completed-workload
logs or traces once their useful conclusions, necessary reproduction inputs and
scripts are retained. Active failure diagnostics remain useful until resolved.
Do not retain every historical execution artifact merely because an older
checkpoint included it. Preserve historical failures and unknown outcomes in
the concise current record without relabeling them as successful executions.

Record three separate facts: **recovery tested**, **source accepted**, and
**saved/delivered**. A recoverable packet can contain unchecked work. A passing
Lean check does not prove archive completeness. An upload attempt is not a saved
artifact. Verify the available durable save route and provide its actual file
identity; report a failed save promptly and stop accumulating unsecured work.

When all work is accepted, the next seed pins that published commit with an empty
source delta. It carries a small current state and necessary operational sources.
Past receipt chains and obsolete startup instructions stay in archived history.
