## Interface design and exact law scopes

Treat a source module signature as abstract carrier/operation parameters and
**separately proved laws**. Its `Parameter`/`Axiom` declarations are requirements
for an implementation, not permission to introduce project axioms. A generic
conditional client must have concrete realizations proving its hypotheses.
Keep payload type and supplied default explicit; no unnecessary global
`Inhabited`, payload equality/order, finite key set, or map-equality decision.

The existing table draft supplies `Ops`, `Laws ops d Valid`, `ObservedEq`,
`observe_set`, function and first-binding list instances, and a shared two-write
client. For the source **Table** contract use its `Valid := True` specialization,
or an equivalent unconditional law record. Do not weaken the source raw-tree
lookup laws by setting this base validity predicate to BST. Enumeration needs
its own invariant parameter. Source `ETableAbs` is a different, weaker scope
for raw states: its observation/update laws explicitly require validity.

| Source interface | Operations/observations and exact laws |
| --- | --- |
| `Table` (50–87) | Carrier `T`, Nat keys, payload `V`, supplied `d`, `empty`, `get`, `set`. For **all** states: `get k empty = d`; `get k (set k v t) = v`; `k ≠ q → get q (set k v t) = get q t`. No representation-invariant premise. |
| `ValType` (100–103) | Payload type and a supplied value only. Recover this by ordinary Lean parameters rather than a new global typeclass. |
| `ETable_first_attempt` (300–320) | Includes Table; adds Boolean `bound` and list `elements`. Unconditional completeness and soundness are interface requirements. The attempted **raw-tree** realization proves completeness but cannot prove soundness without BST. The interface itself can have suitable restricted realizations; do not call it logically inconsistent. |
| `ETable` (375–414) | Includes unconditional Table laws, adds `Valid`, `bound`, `elements`. `Valid empty`; `Valid t → Valid (set k v t)`. All three bound laws remain **unconditional**. Only the displayed elements completeness/soundness laws require `Valid t`. |
| Strengthening for `elements_spec` (766–774) | Retain both absence converses, sorted keys, and no duplicate keys, using the original SearchTree scopes. Inverse completeness needs validity; inverse correctness is valid on all raw trees. The ordinary interface's guarded completeness must not erase that stronger available result. |
| `ETableAbs` (806–847) | Carrier/operations, `Abs : T → Nat → Option V`, and `Valid`. Valid empty/set; `Abs empty = empty_map`; validity-guarded bound, default lookup, update, and elements refinement. | `Queue` (978–992) | Carrier, empty test, enqueue, dequeue, explicit-default peek; **six algebraic laws**, including literal state equality in both dequeue laws. No invariant or decoder occurs. |

For ETable, write the exact enumeration statements as:

```text
Valid t → bound k t = true → get k t = v → (k,v) ∈ elements t
Valid t → (k,v) ∈ elements t → bound k t = true ∧ get k t = v
```

For ETableAbs, preserve the source orientations:

```text
Valid t → map_bound k (Abs t) = bound k t
Valid t → map_find d k (Abs t) = get k t
Valid t → map_update k v (Abs t) = Abs (set k v t)
Valid t → Abs t = map_of_list (elements t)
```

`map_update` inserts `some v`. `map_find` applies `Option.getD d`; `map_bound`
observes `isSome`. An explicitly stored default and absence remain distinct.
`map_of_list` uses first-binding precedence. Equality of that map observation
does not imply raw-list equality, unique keys, or sortedness.

## Realizations and consequential design choices

### Tables, enumeration, and model observations

1. **Function Table:** constant default, application lookup, and accepted source
   update adapter. Prove its three unconditional laws from the accepted Maps
   results. Instantiate String with `""` and the optional Nat-with-zero module.
2. **ListsTable:** raw pair lists, first-match optional lookup followed by the
   supplied default, and prepend update. Duplicate keys are allowed and later
   writes shadow earlier entries. The existing table draft already checks these
   semantics and the shared client; connect its actual definitions to the
   selected public operations.
3. **TreeTable and ETable:** reuse accepted source tree operations. The failed
   first ETable attempt needs a checked malformed-tree counterexample for
   soundness, while retaining the valid raw completeness theorem. For example,
   put a larger key in the left subtree of a smaller root: traversal contains
   it while path-directed lookup/bound can miss it. State concrete keys/values
   and compute both observations through the public source definitions.
4. **Strengthened tree enumeration:** expose validity-guarded absence-to-no-entry,
   unconditional no-entry-for-any-value-to-absence, sorted projected keys, and
   key Nodup. Recover the accepted SearchTree scopes explicitly. Neither the
   default lookup value alone nor an elements-to-map equation supplies these.
5. **ListETableAbs:** the source allows the simple legitimate choice
   `Valid := True`, `elements := id`, `Abs := map_of_list`, prepend set,
   first-match get, and bound from optional lookup. Prove all seven model/
   validity laws. Raw duplicates remain legal: elements-map equality tolerates
   shadowed entries. This realization is not claimed to satisfy the stronger
   ETable membership-soundness or final ListsETable invariant contracts.
6. **TreeTableModel / TreeTableModel':** both optional exercises are mandatory
   here. Use BST validity and, respectively, the accepted inorder/list decoder
   `Abs` and direct structural decoder `Abs'`. Reuse all corresponding source
   refinement theorems, reversing source equation orientations where needed.
   The primed decoder uses overlap-cancelling union, not biased map union.
   Both decoders agree on BSTs; preserve their distinction on malformed trees.
7. **TreeETableSubset:** carrier `{t // BST t}`, empty built with its proof,
   insertion built using preservation, and observations through `.val`.
   Universal carrier laws consume `.property` when needed. No raw-state
   theorem gains an omitted hypothesis merely because this carrier is valid.
8. **ListsETable:** carrier explicitly enforces unique keys on association
   lists; no sortedness restriction. Prefer existing AList/list lemmas through
   the proved constant-family/product adapter. `elements` returns the stored
   association list. Set replaces/removes an old key while preserving uniqueness;
   it cannot simply prepend duplicates. Exact representation/projection and
   update equations must be retained, together with all ETableSubset laws.

Source `elements_spec` additionally asks for a *nicely encapsulated* interface:
write clients generic in operations/laws with public payload/default parameters,
and instantiate the tree realization. Do not expose tree constructors merely
to make the generic client proof easier.

### Queue equations and source recurrence

The source Queue laws are exactly:

```text
is_empty empty = true
is_empty (enq q v) = false
peek d empty = d
peek d (enq q v) = peek v q
deq empty = empty
deq (enq q v) = if is_empty q then q else enq (deq q) v
```

Implement ListQueue with `[]`, `List.isEmpty`, append-singleton, `List.tail`,
and `List.headD`. General payload types are possible without extra assumptions;
retain the source Nat specialization. Prove the last equation with actual
state equality and its literal `q` empty branch.

The source pair queue has no validity restriction:

```text
Abs (f,b) = f ++ b.reverse
empty = ([],[])
is_empty (f,b) = f.isEmpty && b.isEmpty
enq (f,b) v = (f,v::b)
deq ([],[]) = ([],[])
deq ([],b) = match b.reverse with [] => ([],[]) | _::rest => (rest,[])
deq (_::rest,b) = (rest,b)
peek d ([],[]) = d
peek d ([],b) = (b.reverse).headD d
peek d (v::_,b) = v
```

The redundant empty-front branches reflect the original pattern matching;
an implementation using `((b.reverse).tail,[])` must prove the exact value
equation bridge. Preserve the actual reversal operation when instrumenting
cost; an extensional simplification alone is not cost correspondence.

Prove the four QueueAbs laws on **every raw pair**. Also separately prove
`is_empty q = true ↔ Abs q = []` for this concrete source realization, marking
it as an additional implementation theorem, not a consequence of the four-law
signature. A variant of the abstract signature with arbitrary `is_empty`
demonstrates the missing-law boundary. For existing AbstractFIFO clients,
prove an actual optional-head observation (and its relationship to default
peek) before constructing Simulation evidence.

Do not assign the pair realization the stronger Queue raw-state law. The
source recurrence gives the following **pending checked counterexample**:
with `q=([],[1])`, enqueueing 2 and then dequeuing yields `([2],[])`, whereas
enqueueing 2 after dequeuing q yields `([],[2])`. Both decode to `[2]`, but
the states differ. This is why a decoder contract is material.

### Encapsulation and subset examples

Lean adaptation must distinguish hiding carrier/operations from hiding the
payload type and default. Preserve the fully abstract, exposed-payload-only,
and exposed-payload-plus-default cases of SimpleTable. Prove a generic client
from the law `get_empty_default`, then instantiate String/default `""` without
unfolding a tree. The source's module-sharing constraints specify equal types
and values; they are unrelated to heap sharing and require no new generativity
framework. Do not claim Lean namespace, `private`, or `opaque` behavior is an
exact emulation of Rocq module sealing.

For even naturals use `{n : Nat // Even n}`, construct 2 with its actual proof,
recover both `.val` and `.property`, and relate the displayed witness equation
to the source convention where needed. Lean coercions or numeral instances may
make a source `Fail` command succeed, so preserve the lesson and checked
projection/typing behavior rather than fabricate the same error.

The sandbox's computational `sig` is ordinary `Subtype`; its `ex` is ordinary
`Exists`. Recover a witness from the former; explain the prohibited general
elimination of the latter into computational data. Noncomputable classical
choice is a different boundary, not an implementation of the failed projection.

For source vectors retain `{p : List V × Nat // p.1.length = p.2}` or a proved
equivalent package. A concrete vector, constructive cons, and constructive
append must establish their stored-length proofs. The two requested correctness
theorems observe the exact list projection. Reuse `List.Vector` operations
through a projection-preserving equivalence; root Array-backed `Vector` requires
a separate representation bridge and is not the automatic source alias.

## Resource prose and qualifications

- The sentence at 248–249 calling functions/lists inefficient and BSTs more
  efficient is conditional on representation, lookup history, tree shape,
  primitive costs, and workload. Reuse the accepted SearchTree height/count
  results and recorded function-history boundaries. An unbalanced BST does
  not supply a universal logarithmic improvement; no universal runtime ordering
  is required or justified.
- ListQueue explicitly recommends linear enqueue (996–998). Under a structural
  list-work model, append visits its old prefix; prove the selected operation's
  recurrence/erasure and a linear bound, with an unbounded family showing the
  work grows. Literal constructor requests and native allocation remain distinct.
- The blanket amortized-constant statement at 1074–1076 is false for repeated
  observations of the displayed pair implementation. Empty-front states with
  arbitrarily long back lists are reachable using enqueue. Peek reverses the
  back without returning an updated state, so repeated peeks repeat that work.
  Reuse the checked staged `QueuePeekDraft` counterexample and its connection to
  `Resources.run`/potential accounting, after bridging the integrated exact
  source definitions. A state-only potential cancels on unchanged-state peeks.
- Give the intended positive result its proper scope: for linear histories of
  **enqueue/dequeue** with a linear reverse model, back-list length provides the
  usual potential (or a constant multiple for the chosen weights). Each next
  operation consumes the preceding state; arbitrary reuse of older persistent
  versions is not thereby covered. Prove measured erasure and step charges, retaining initial
  and final potential, then use the existing trajectory theorem. A model that
  instead instruments a quadratic structural reverse does not establish this
  positive linear-history bound; select and justify the actual modeled reverse.
  Any repair that caches/rebalances during peek is a different operation and
  must not replace the source implementation silently.
- The existing staged negative result instruments structural reverse with
  append traversal and needs only a full-traversal lower bound. It therefore
  also rules out a uniform charge for repeated full **linear** reversals.
  Its exact recurrence is `R(0)=0`, `R(n+1)=R(n)+n+1`. It charges nonempty
  reverse/append visits, not nil tests, dispatch, endpoint head access, pair
  construction, or enqueue. This omission does not invalidate the lower bound;
  do not relabel it a complete runtime count. A positive total-work bound must
  account for the other bounded local work, or be labeled traversal cost only.
  It does not certify compiler code, memoization, garbage collection, or a
  measured Lean runtime.
- ListsETable's final prose (1480–1487) describes a linear set operation. For
  the selected unique-key list update, instrument actual key comparisons/list
  traversal, prove a linear upper bound and an appropriate worst case (for
  example an absent key). A front match can be cheap; do not state that every
  invocation takes exactly the list length or that every possible representation
  must satisfy an unproved lower bound.
