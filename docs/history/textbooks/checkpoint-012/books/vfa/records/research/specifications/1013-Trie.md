## Architecture and directly inspected reuse

Reuse existing carriers and the accepted table/resource seams. A small
`Applications/Tables/PositiveTrie.lean` adjoining the accepted functional/tree
tables is a reasonable location; arithmetic/key adapters belong with the
eventually integrated positive-key seam, and measured clients can occupy an
appropriate `Applications/Resources` module. Final locations depend on accepted
predecessors. Cross-domain applications belong in `Examples`. No new positive
number, binary-tree, map, comparator, resource, or word-machine hierarchy is needed.

The trie payload may have any universe and needs no equality, order, or global
`Inhabited` instance. Its default is an explicit payload. PosNum is the concrete
key representation, so insertion/lookup require neither numeric comparisons nor
an ordering of keys. Generic collision specifications can use `[DecidableEq K]`;
the three concrete source key types supply constructive equality. Keep any
classical reasoning inside proofs separate from executable operations.

## Exact mathematical requirements

The notation in this section specifies future obligations, not new Lean code.
Write `H`, `O p`, `I p` for PosNum one/bit0/bit1; `ν p` for unshifted numeric
value; `b p` for `PosNum.natSize p`; `e n` for shifted encode; `d p` for shifted
decode; and `B(l,v,r)` for `BinaryTree.node v l r`.

### Positive arithmetic, printing, and the comparison exercise

Preserve all constructor equations: `ν H = 1`, `ν (O p) = 2*ν p`,
`ν (I p) = 1+2*ν p`. Positivity and numeric injectivity establish canonical
representation; there is no zero constructor and no redundant high zero.
The source ten is `O (I (O H))`, with numeric value 10 and shifted key 9.

The printer must have the source equations `P H = [1]`,
`P (O p) = P p ++ [0]`, `P (I p) = P p ++ [1]`. A proved adapter to
`((ν p).bits.reverse).map Bool.toNat` can reuse the library digit observation.
Retain the all-input recurrence, exact ten result `[1,0,1,0]`, length `b p`,
and 0/1/leading-one meaning. If a literal append-based printer is selected,
its append work is not covered by linear bit-traversal claims for arithmetic.
The output-equivalent bits/reverse realization is not an allocation-cost identity.

Reuse `PosNum.succ` with its exact equations `S H = O H`, `S (O p) = I p`,
`S (I p) = O (S p)` and prove/reuse `ν (S p) = ν p + 1`.

The source addition carries a Bool through its own recurrence. All eighteen
branches remain required, including the asymmetric base cases that call
successor on the remaining child. In this table `A₀/A₁` mean source carry false/true:

| Inputs | Carry false | Carry true |
| --- | --- | --- |
| `I p`, `I q` | `O (A₁ p q)` | `I (A₁ p q)` |
| `I p`, `O q` | `I (A₀ p q)` | `O (A₁ p q)` |
| `I p`, `H` | `O (S p)` | `I (S p)` |
| `O p`, `I q` | `I (A₀ p q)` | `O (A₁ p q)` |
| `O p`, `O q` | `O (A₀ p q)` | `I (A₀ p q)` |
| `O p`, `H` | `I p` | `O (S p)` |
| `H`, `I q` | `O (S q)` | `I (S q)` |
| `H`, `O q` | `I q` | `O (S q)` |
| `H`, `H` | `O H` | `I H` |

Prove for both carries and all inputs
`ν (A_c p q) = (if c then 1 else 0) + ν p + ν q`.
Source `add` is `A₀`; conclude its exact arithmetic theorem. Numeric injectivity
and `PosNum.add_to_nat` then give `A₀ p q = p+q` and, if useful,
`A₁ p q = PosNum.succ (p+q)`. These are proved representation adapters;
the source carry implementation and its measured recursion remain explicit.

Reuse `Ordering` for source Eq/Lt/Gt and `PosNum.cmp` as the completed exercise.
Its source-facing equations must cover this whole table:

| Inputs | Required comparison result |
| --- | --- |
| `H`, `H` | eq |
| `H`, `O q` or `I q` | lt |
| `O p` or `I p`, `H` | gt |
| `O p`, `O q` | compare p q |
| `I p`, `I q` | compare p q |
| `I p`, `O q` | lt if compare p q is lt; gt otherwise |
| `O p`, `I q` | gt if compare p q is gt; lt otherwise |

Retain the source match-valued theorem for all inputs: lt means `ν x < ν y`,
eq means `ν x = ν y`, gt means `ν y < ν x`. Actual key equality follows in
the eq branch. The placeholder catch-all returning lt is removed as requested,
not accepted as a valid algorithm; the diagnostic case compare H H would
otherwise claim `1 < 1`. No custom comparison datatype or competing order
instance is justified. Color's later bit order is still a separate contract.

Use `ZNum` to explain and realize `Z0/Zpos/Zneg`: numeric observation is
0, `ν p`, and `-ν p`. Its positive and negative constructors are disjoint and
nonzero. Existing signed arithmetic/order laws support the later source uses.
The source explicitly declines to implement all signed arithmetic at 325–330;
this is not a requirement to reimplement Mathlib's integer library.

### Trie operations and low-bit-first paths

The source carrier is `V × BinaryTree V`, including its stored default.
The constructor adapter reverses the source node argument order, not the
children. `look d i t` reuses `BinaryTree.getOrElse i t d`; expose these equations:

| Operation/input | Required result |
| --- | --- |
| `empty d` | `(d, Leaf)` |
| `look d i Leaf` | d, for every i |
| `look d H B(l,v,r)` | v |
| `look d (O i) B(l,v,r)` | look d i l |
| `look d (I i) B(l,v,r)` | look d i r |
| `ins d H v Leaf` | B(Leaf,v,Leaf) |
| `ins d (O i) v Leaf` | B(ins d i v Leaf,d,Leaf) |
| `ins d (I i) v Leaf` | B(Leaf,d,ins d i v Leaf) |
| `ins d H v B(l,w,r)` | B(l,v,r) |
| `ins d (O i) v B(l,w,r)` | B(ins d i v l,w,r) |
| `ins d (I i) v B(l,w,r)` | B(l,w,ins d i v r) |
| `lookup i (d,t)` | look d i t |
| `insert i v (d,t)` | (d,ins d i v t); the stored default is preserved |

Insertion recurses on the key, including its recursive construction below a
Leaf; tree size alone is not a decreasing measure in those branches. It creates
default-valued intermediate nodes. The stop marker H selects the current root,
not its right child. For ten the path is left, right, left, stop; the printed
high-to-low list must not be used directly as that path.

Retain the exact `three_ten` constructor result. In source argument order its
tree is `B(B(Leaf,false,B(B(Leaf,true,Leaf),false,Leaf)),false,B(Leaf,true,Leaf))`,
paired with false. The queried positive keys `[3,1,4,1,5]` return
`[true,false,false,false,false]`; a connected query at 10 must return true.
These are constructor/lookup results, distinct from the shifted Nat abstraction.

For the word-trie prose, a small adapter can use a Bool word obtained from the
outer O/I constructors, omitting H. The existing WordCoalgebra has output d at
Leaf and v at a node, and transitions to the left/right child, with Leaf
absorbing. Prove `run` on this word agrees with `look`. This is ordinary finite
word semantics with arbitrary output values; its Boolean-output specialization
can be read as a recognizer. A fixed finite tree has finitely many reachable
subtree states. The whole BinaryTree carrier need not be finite. The absorbing semantic run
may continue over unused suffix bits after Leaf, while actual look stops there;
no equality of traversal costs is inferred. Do not replace the table with the
depth-indexed trie from language snapshots.

### Algebraic laws, shifted abstraction, and observational equality

First prove, without an invariant or payload assumptions:

- `look a j Leaf = a`.
- `look a k (ins a k v t) = v`, for every a, k, v and raw t.
- `j ≠ k → look a j (ins a k v t) = look a j t`.

Both uses of the default in the insertion/lookup law are the same a. A theorem
allowing unrelated insertion and lookup defaults would be false at newly
created filler nodes. Expose the corresponding table lookup equations for
every raw `(default, tree)` pair, and use the accepted table Laws with
`Valid := True`. A fixed empty default does not require all raw table pairs to
store that same default; the get/set laws hold for each pair's own default.

The simplest correct source invariant is **`is_trie t := True`**. All raw trees
satisfy the total-table specification. Empty validity and insertion preservation
must still be provided as actual source-facing theorems, not left as admissions.
No BST ordering, balance, canonical pruning, finite history, or payload
inequality is needed. A stronger invariant would unnecessarily weaken the source.

Use the staged key seam with the exact offsets:

| Observation | Required equation |
| --- | --- |
| Unshifted positive value | `ν p ≥ 1`; `ν (e n) = n+1` |
| Shifted natural key | `d p = (ν p).pred`; `ν p = d p + 1` |
| Positive round trip | `e (d p) = p` |
| Natural round trip | `d (e n) = n` |
| Injectivity | d injective on positives; e injective on naturals |
| Boundary | `e 0 = H`, `d H = 0`; constructor ten has shifted key 9 |

`PosNum.ofNat 0 = PosNum.ofNat 1 = H` is the existing checked counterexample
to an unshifted encoding; never substitute it for e. PNat stores the numeric
value, not d. `PosNum.pred H = H` likewise cannot supply this decoder.

Define the mathematical observation `abstract t n = lookup (e n) t` and
relation `Abs t m ↔ abstract t = m`, exactly as in the source. Required laws:

- `Abs (empty default) (fun _ => default)`.
- `is_trie t → Abs t m → lookup i t = m (d i)`.
- `is_trie t → Abs t m → Abs (insert k v t) (Function.update m (d k) v)`.

Prove the stronger unconditional observation equations first where convenient;
retain wrappers with the source premises. `lookup_relate` uses `e (d i)=i`,
not a mistaken unshifted cast. For `insert_relate`, compare query `e n` with k,
equivalently n with `d k`, using the established inverse/injectivity laws.
Use Maps' accepted equality-test orientation adapter or
`Function.update_comp_eq_of_injective` with the actual inverse substitution.

Package insertion/empty/lookup correspondence through existing table laws and
Squares. Recover the familiar shadowing, commuting-distinct-writes, and
self-update equations at **total lookup observations** from Maps. No raw-tree
extensionality principle follows. In particular empty d and insertion of d at
H into that empty table observe the same function but have different trees.

This source trie stores total values at all materialized nodes. The optional
result of `BinaryTree.get` detects a materialized path, not whether that key
was explicitly written: insertion at O H creates a root filler with value d.
Neither absence nor write history can be recovered from the chapter's total
lookup. Do not label it a partial finite map merely because a later FMaps
implementation is mentioned. An optional-payload trie and its binding laws
would be a different, separately proved realization for Color's later needs.
Key bijectivity also does not make the table decoder injective or onto all
unrestricted `Nat → V` functions.

### Three collision programs and an independent result specification

Preserve all three source control recurrences: query the current Boolean table;
if true increment the counter and leave the table unchanged; if false leave
the counter and write true at that key. Their initial tables return false.
VerySlow uses Nat keys and `c+1`; RatherSlow uses signed binary keys and a
signed counter `c+1`; FastEnough uses positive keys, the trie, and `1+c`.
The semantic equality of the counter increments does not identify their source
reduction costs.

Use `ZNum → V` and accepted `Function.update` for the RatherSlow total-map
realization, proving its Boolean equality branch agrees with source signed-key
equality via Int observation/injectivity. A direct Int-facing adapter can then
recover the usual mathematical statement. The carrier remains unbounded and
supports negative keys; a positive-only trie is not a replacement for this
whole signed-key program. Counter-cost claims start at zero and use the proved
nonnegative trajectory, even though the general loop accepts an arbitrary c.

The independent output specification for any finite key list xs is
`xs.length - xs.dedup.length`. This counts occurrences after the first of each
key; it is not the number of equal unordered index pairs. Prove each complete
source program returns that count (after casting the RatherSlow result to Int).
Retain the invariant that the table returns true exactly for keys seen in the
processed prefix and that the counter counts prefix repetitions. Use a finite
seen-key witness or the prefix itself; do not presume arbitrary Boolean total
functions have finite support. A reusable client over the accepted table Ops
and laws plus the actual state/observation bridge can discharge all three
realizations. A small concrete loop-to-fold equation permits existing reachable
fold fusion and measured run; no new client language is needed.

All three exact source lists `[3,1,4,1,5,9,2,6]` must return 1 in their own
key types. For a general comparison across key representations, use an explicit
injective list map and `dedup_map_of_injective`. Mapping Nat by e increments
the numeric labels; it does not preserve those source positive numerals.
Mapping a positive list by ν keeps its numeric labels, while mapping by d
shifts them. Both preserve duplicates, for separately proved reasons. In
`Abs_three_ten`, positive 3 and 10 correspond specifically to Nat 2 and 9.

## Resource and execution obligations

All counts below are future checked obligations tied by value erasure to the
actual chosen recurrence/realization. They are not new proved results in this
plan. State fixed primitive tariffs, count instrumented operations rather than
proof execution, and separate bit visits, equality tests, constructor events,
and loop/counter overhead. Native Nat/Int operations, compiler sharing,
allocation, GC, and elapsed time are not certified by these value equations.

### Positive arithmetic and exact bit length

Use `b H=1`, `b(O p)=b p+1`, `b(I p)=b p+1`, reusing PosNum.natSize.
Prove `2^(b p-1) ≤ ν p < 2^(b p)` and `b p = Nat.log 2 (ν p)+1`.
For 1 and powers of two this differs from an unqualified rounded-up log.

| Actual operation/model | Required count and consequence |
| --- | --- |
| Successor constructor-pattern visits, including the terminal call | `Svis H=1`, `Svis(O p)=1`, `Svis(I p)=1+Svis p`; prove `Svis p ≤ b p`. Carry chains attain the linear-in-bit-length worst case. |
| Carry addition constructor-pattern visits, also charging all nested successor visits | One for each entered `addc` branch; add the recursively called addc or successor cost prescribed by that branch. Prove the combined cost is at most `max (b p) (b q)`. If a different fixed local tariff is selected, retain a derived explicit constant multiple. Counting only structural calls on p misses the remaining successor work on q. |
| Completed `PosNum.cmp` constructor-pair visits | One per comparison call, terminating when either input is H; both nonterminal inputs recurse once. Prove exact count `min (b p) (b q)` and erasure to `PosNum.cmp`. Thus it is bounded by b p, but is not Θ(b p) for every y: y=H terminates immediately. Comparing equally long keys supplies a worst-case family. |
| Addition result size | With either carry, `max (b p) (b q) ≤ b(A_c p q) ≤ max (b p) (b q)+1`. This connects the measured bound to logarithm of the result rather than just the termination measure. |

The carry bound above follows the actual eighteen-branch recursion: simultaneous
recursive calls strip both arguments; a terminal call may run successor on a
strict child of the remaining argument. Retain terminal costs and discharge
each branch. Existing PosNum.add correctness is not a substitute for this count.
Subtraction and general signed multiplication are background at 325–330, not
additional unshown source algorithms to invent here.

positive one; no probability framework or uniform-random assumption is needed.
Let the digit observation be `(ν p).bits`, using the existing Nat.bits API.
Prove its three constructor equations, nonemptiness, canonicality, numeric
meaning through `BinaryCounter.value`, and length b p. Then prove the exact
bridge `digits (PosNum.succ p) = BinaryCounter.inc (digits p)`.

For the **bit-write** convention used by BinaryCounter, instrument the actual
PosNum successor with charges 2 at H, 1 at O p, and 1 plus recursive charge
at I p. The H case writes the old low bit to zero and adds a new high one;
charging it only one would fail the adapter. This is a changed-digit model,
not a statement that a runtime allocates two distinct heap objects for H.
Prove the measured bridge to `BinaryCounter.incWithCost`, not just numeric
agreement. Constructor visits are bounded by these writes; they are a separate
observation from physical allocation.

Reuse `flipCost_potential` / `totalCost_potential` along the same actual source
trajectory. For n increments from p, retain
`totalWrites + ones(digits(final p)) = 2*n + ones(digits p)`.
The generic bound keeps initial potential. Starting at H gives initial potential
1; every final positive has at least one one bit, hence `totalWrites ≤ 2*n`.
The finite input states before N increments are exactly 1,…,N and the final
value is N+1. This proves a constant average write bound for N>0. Observing N
states without incrementing the last uses N-1 transitions and must be labeled
accordingly. Do not conflate this sequential result with arbitrary persistent
branches or an independently sampled expected-cost theorem.

Use `ZNum.succ (.pos p) = .pos (PosNum.succ p)` for the exercise's signed
presentation. The zero-start counter in RatherSlow additionally has the zero
branch, with the usual empty digit list and one first write. Prove that bridge
and nonnegative-counter preservation before reusing zero-start BinaryCounter
accounting. The negative branch is not traversed by that complete program.

### Collision complexity with independent size parameters

Use n = input length, D = number of distinct input keys, M = a bound on natural
key magnitude (or absolute signed magnitude), and B a bound on positive bit
length. For signed keys take `bZ z = max 1 (Nat.size (Int.natAbs (z : Int)))`
and require `bZ z ≤ B` on the input; this assigns zero length one and leaves
the sign dispatch as a separate constant charge. Let Dᵢ be the
number of distinct keys in the processed prefix, so Dᵢ ≤ D ≤ n. Empty input
must be handled directly; logarithmic summaries use `1 + log(n+1)` or explicit
positive-size hypotheses. The source uses one N for several of these quantities;
its asymptotic chain is obtained only after a bounded-key specialization.

For the book's bounded-key comparison, select `0 ≤ key < 2*n` for the
imperative array model, or initialize `2*n+1` cells if the endpoint 2*n is
included. State the choice. Natural keys bounded by a constant multiple of n
give M=O(n); binary encoding uses ν(e k)=k+1, so its B bound includes that
offset. Derive the displayed upper-bound progression under these assumptions:
O(n³), O(n² log n), O(n(log n)²), and O(n log n), with small-size corrections.
Use the exact bit-length form first and standard asymptotic packaging second.

A useful tight lower-bound family for the unary-chain stage is the distinct
list n,n+1,…,2*n-1. Every fresh lookup traverses all previous bindings and each
equality takes at least n+1 terminal-inclusive unary calls. Prove the resulting
`(n+1)*n*(n-1)/2` lower bound and the matching cubic upper specialization,
with the empty/small cases retained. No statement says every input is cubic.
For binary/Redblack/trie stages, upper bounds must not be relabeled Θ without
a corresponding lower family and the same primitive model.

Tries depend on key length even with just **one distinct inserted key**.
Retain the family `O` iterated h times on H: numeric value `2^h`, bit length
h+1. Inserting true into an empty-false table creates h+1 nodes and querying
that key visits h+1 nodes, despite one explicitly inserted/nondefault key.
Intermediate default nodes are not distinct insertion events. This rules out
an unconditional O(log D) traversal claim based only on the number of writes.

Native-positive lookup does not encode a Nat query. The function
`abstract t n` includes e only as a mathematical observation unless its execution
is explicitly selected. `PosNum.ofNatSucc` recurses on n, so neither shifted
bijectivity nor the source-to-function square proves that repeated Nat-facing
lookup runs in logarithmic time. Account separately for key construction,
numeric casts, input preprocessing, printing, and any alternative conversion.

The chapter requests no timing experiment. Reproduce its computational examples
as kernel-checked facts and executable demonstrations under the later workflow;
do not turn them into universal performance evidence. The categorical assertion
that pure functions cannot have constant indexed updates is model-dependent:
retain the declared persistent representation and primitive-access assumptions,
not an unsupported impossibility theorem. Mutable arrays/IO and finite-word
native primitives need their own realization contracts if discussed.
