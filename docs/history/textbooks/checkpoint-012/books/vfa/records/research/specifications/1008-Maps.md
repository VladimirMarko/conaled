## Semantics and smallest useful extension

The source total-map type is exactly `Nat → V`. It does **not** contain a
default field, a membership predicate, or a finite-support witness. The default
is an explicit argument to the constant empty function. An arbitrary function
is a valid total map, even if no finite history of writes constructs it.
The source partial-map type is exactly `Nat → Option V`; its empty map returns
`none` and setting a value writes `some v`. Its type likewise imposes no finite
support restriction. Do not replace either function space with `Finsupp`,
`Finmap`, a finite hash map, or an ordered-tree carrier.

Use the existing `Function.update` for the reusable key generalization
`K → V`, under `[DecidableEq K]`; Nat supplies a computable instance.
Independent key and value universes are available. Empty maps need no equality
decision; executable updates need only key equality, not key order, value
equality, a global `Inhabited V`, or `Nonempty K`. Use an explicit default when
one is needed. Do not obtain an executable arbitrary-key update by silently
substituting classical equality.

`Function.update_apply` tests **query = written key**, while the source Boolean
Nat expression tests **written key = query**. Prove a Nat source-facing branch
equation using symmetry and the Nat equality decision/reflection; preserve both
branches and actual `some`/`none` results. Exact equality of resulting functions
is the required adapter. No compiler-code, allocation, or evaluation-cost
identity follows from this equation.

Prefer a small `Applications/Tables/Functional.lean` for any missing reusable
partial-map operations, source branch adapter, and total/partial observation
bridge, with connected uses in `Examples/FunctionalMaps.lean` or an appropriate
existing composition module. These locations are proposals, not a new mandated
hierarchy. A source-name alias is useful only when it makes later chapter
statements clearer. Map the six total-map laws directly to Mathlib wherever
the exact source contract is already present; do not copy their proofs or
create a parallel function-update library merely to reproduce names.

The staged `Ops`, `Laws`, and `ObservedEq` separate operations, invariants, and
observations for later table representations. Maps needs no new record to prove
the algebra of functions. Integrate only the useful observation seam and checked
clients at this chapter, or explain a concrete present need for more of the
draft. The ADT module signatures, trees, enumeration, and invariant interfaces
remain obligations of their own chapters. Preserve the draft for those consumers.

## Inspected reusable APIs and their boundaries

The Function APIs below were read in pinned
`Mathlib/Logic/Function/Basic.lean:634–790`; they are existing declarations,
not proposed or newly compiler-checked wrappers.

| Existing API | Exact use and important hypothesis/orientation |
| --- | --- |
| `Function.const`, ordinary function application, `funext` | Constant empty map, lookup, and extensional equality. No new functional-extensionality axiom or function-equality decision procedure is needed. |
| `Function.update_apply f k v q` | Nondependent form: `Function.update f k v q = if q = k then v else f q`. This supplies the value-branch bridge after reversing the source's equality test. |
| `Function.update_self k v f` | `Function.update f k v k = v`; no condition on the previous value. |
| `Function.update_of_ne h v f` | With `h : q ≠ k`, gives `Function.update f k v q = f q`. The source total law supplies `k ≠ q`, so use its symmetry. |
| `Function.update_idem v₁ v₂ f` | `update (update f k v₁) k v₂ = update f k v₂`; the later write wins. |
| `Function.update_eq_self k f` | `update f k (f k) = f`; equality of functions, not only a selected lookup. |
| `Function.update_comm h v₂ v₁ f` | With `h : k₂ ≠ k₁`, gives `update (update f k₂ v₂) k₁ v₁ = update (update f k₁ v₁) k₂ v₂`, matching the source order. |
| `Function.comp_update h f k v` | `h ∘ update f k v = update (h ∘ f) k (h v)`. Value mapping needs **no injectivity** of `h`; use it for the optional-to-default observation bridge. |
| `Function.update_comp_eq_of_injective g hi k v` | Reindexing through an injective `i : K → L` preserves the one-key update: `update g (i k) v ∘ i = update (g ∘ i) k v`. Requires equality decisions on both key domains and proved injectivity. It does not authorize arbitrary noninjective key transport. |
| Staged `withDefault`, `withDefault_update`, `binding_iff`, `forget_default_not_injective` | Preserve the difference between absence and an explicitly stored default, and prove the exact amount of information retained. Their types and concrete cases were read; integration still needs the ordinary candidate gates. |
| Staged `functionOps`, `functionLaws`, `associationOps`, `associationLaws`, `twoWrites_equivalent` | Existing preparation for a shared two-write/get client. Function and first-binding list observations agree under proved laws; their raw carriers and histories are not equal. |
| `Incremental.VectorSum.assign`, `applyPatch`, `total_assign` | The existing application uses `Function.update` on `Fin n → G` and an ordered `List.foldl` patch. Its sum theorem requires `AddCommGroup G`. It is a concrete consumer of the generalized update semantics, not an implementation of unrestricted Nat-key partial maps. |
| `Dijkstra.Store.lookup_write` | A bounded Vector write has `lookup (write a i x) j = if i = j then x else lookup a j`. A decoder can connect it to function update. The finite domain and default-free Vector carrier must remain explicit. |
| `SquareKit.ListFusion.foldl_reachable` | If a retained client is generalized to arbitrary write histories, reuse this fold transport with its base invariant, preserved step, and commuting observation equation. A new generic command executor is unnecessary for this chapter. |

For cross-domain client placement, ADR 0010 and the existing
`Sequences.AbstractFIFO.Simulation` illustrate separate operation data and
semantic laws, with composition through the established relational interfaces.
Maps does not need a new universal map/simulation hierarchy. Existing structures
should be used only where they add a real reusable contract.

## Complete source-record and exercise obligations

**Every row remains pending chapter integration.** Below `T V := Nat → V`,
`P V := Nat → Option V`, `E d := fun _ => d`, `U m k v := Function.update m k v`,
`empty := E none`, and `put m k v := U m k (some v)` are planning notation.
They denote the intended observations; they are not new Lean declarations.
`EEx` marks one of the six standard exercises.

| Source inventory ID | Exact source obligation and intended treatment |
| --- | --- |
| `Maps.total_map@28` | `T V`, with Nat keys and arbitrary payload type; an alias to the function type suffices. Retain the source Nat specialization of any generic-key interface. |
| `Maps.t_empty@34` | Constant `E d`, with supplied `d : V`; lookup at every key is `d`. No default field or finite-support premise is added to `T V`. |
| `Maps.t_update@42` | `U m k v`, connected to the source equality-test branch at every query and hence as a function. Equality-test argument reversal must be justified. |
| `Maps.examplemap@54` | The exact function `U (U (E false) 1 false) 3 true`. Writing the default at 1 is retained in the expression even though total observation cannot detect that binding history. |
| `Maps.update_example1@61` | That same example map at 0 is `false`; instantiate different-key/empty lookup laws. |
| `Maps.update_example2@64` | At 1 it is `false`; instantiate different-key then same-key lookup, or use the self-update theorem with the exact example bridge. |
| `Maps.update_example3@67` | At 2 it is `false`; instantiate the two distinct-key observations and empty lookup. |
| `Maps.update_example4@70` | At 3 it is `true`; instantiate the latest same-key write. |
| `Maps.t_apply_empty@83` **EEx** | `∀ V k d, E d k = d`. Direct reduction of the real constant function is appropriate. |
| `Maps.t_update_eq@94` **EEx** | `∀ V (m : T V) k v, U m k v k = v`. Existing `Function.update_self`. |
| `Maps.t_update_neq@107` **EEx** | `k₁ ≠ k₂ → U m k₁ v k₂ = m k₂`. Written key is `k₁`, query is `k₂`; adapt `update_of_ne` by `Ne.symm`. |
| `Maps.t_update_shadow@123` **EEx** | `U (U m k v₁) k v₂ = U m k v₂`. Existing `update_idem`, as equality of complete functions. |
| `Maps.t_update_same@135` **EEx** | `U m k (m k) = m`. Existing `update_eq_self`; no finite construction or representation-validity premise. |
| `Maps.t_update_permute@146` **EEx** | `k₂ ≠ k₁ → U (U m k₂ v₂) k₁ v₁ = U (U m k₁ v₁) k₂ v₂`. Existing `update_comm` with this exact key/value order. |
| `Maps.partial_map@161` | `P V = T (Option V)`. This is an unrestricted optional-valued function space; no promise of finitely many bindings or enumeration. |
| `Maps.empty@163` | Constant `none` partial map. Absence is represented explicitly rather than by a chosen payload value. |
| `Maps.update@166` | `put m k v = U m k (some v)`. The operation inserts a payload and never uses `none` as a synonym for a stored default. |
| `Maps.apply_empty@173` | `∀ V k, (empty : P V) k = none`, by specialization of the total-map result. |
| `Maps.update_eq@179` | `put m k v k = some v`, by total same-key update. |
| `Maps.update_neq@186` | **Source variable order:** `k₂ ≠ k₁ → put m k₂ v k₁ = m k₁`. Written key is now `k₂`, query is `k₁`; do not copy the preceding total-law variable names blindly. |
| `Maps.update_shadow@195` | `put (put m k v₁) k v₂ = put m k v₂`, by total shadowing at `Option V`. |
| `Maps.update_same@202` | `m k = some v → put m k v = m`. Retain the `some v` premise; updating an absent key to a default payload does not preserve the partial map. |
| `Maps.update_permute@210` | `k₂ ≠ k₁ → put (put m k₂ v₂) k₁ v₁ = put (put m k₁ v₁) k₂ v₂`, by total commutation at `Option V`. |

## Connected cases and statement review

1. Recover the four source Bool observations at 0, 1, 2, and 3 for the exact
   function `examplemap`. The staged association-list example alone is not this
   function-valued declaration. Either derive the observations directly through
   the public update laws or connect the existing shared client to `functionOps`
   and prove it is this expression. Keep the connection to the general laws.
2. Show later-write shadowing at a repeated key, self-update, and two distinct
   updates commuting. Retain a same-key/different-value case where swapping
   updates changes the observed result, so the commutation premise is material.
   A Bool-key instance demonstrates that only key equality is needed.
3. Integrate or specialize the staged default-forgetting bridge
   `withDefault d m := fun q => (m q).getD d`. Its update equation follows from
   `Function.comp_update` using `h := fun o => o.getD d`; no injectivity of that
   observation is assumed. Check `none` versus `some false` with default false:
   equal total observations, unequal partial maps and different bound bits.
   Consume the proved bridge/noninjectivity fact rather than treating a textual
   counterexample as a proof. This also exercises the premise in partial
   `update_same`.
4. Retain one meaningful composition with an existing realization. A small
   `Dijkstra.Store` decoder result can identify its complete lookup function
   after a write with `Function.update`; `lookup_write`, symmetry, and
   `funext` supply the existing ingredients. Alternatively, a connected
   `Incremental.VectorSum.assign` client can use generalized shadowing or
   commuting updates and its `total_assign` theorem. Put a cross-domain theorem
   in `Examples`, preserve the finite domain and group assumptions, and do not
   duplicate either application implementation.

For all claims, review quantifier domains, independent universes, query/write
orientation, later-write precedence, function equality versus lookup equality,
and the partial self-update premise. Nonvacuity comes from actual Nat/Bool
instances and concrete defaults; avoid adding unnecessary inhabitants to generic
statements. Raw association-list membership is not current binding when keys
are shadowed. Default-valued lookup equality does not recover partial-map
equality. Reindexing keys and mapping values have different hypotheses; the
former's injectivity must not be inferred from the latter's unrestricted law.

No arbitrary-history algorithm, elements enumeration, tree invariant,
allocation model, or complexity theorem is needed to complete the exact Maps
source. If a useful future extension is deferred, name its consuming chapter
instead of silently treating it as completed here.

## Remaining work and chapter acceptance

The pending work is the exact Nat branch/source-name connection, complete
source-to-public-theorem coverage, optional-valued operations and their six
specialization laws, connected source and boundary cases, and the small
observation/composition seam selected for integration. Existing Mathlib algebra
substantially discharges the mathematical work but does not by itself update
coverage, connect the source cases, or establish this candidate's acceptance.

After #1007 acceptance, use the existing implementation/example-driven loop,
capture that accepted predecessor as the fixed chapter base, and preserve
statement-review evidence. Integrate every module/example in the public
entrypoint and exhaustive audit roots. Run appropriate focused checks and the
ordinary isolated `./check.sh --candidate HEAD` under the pinned Nix environment,
with current coordinator-selected worker settings. Retain actual failures and
corrections. Satisfy the README's applicable audit-regression requirement and
its managed `ProofAudit` prerequisite as documented in the environment guidance.
Both independent Standards and Spec axes must pass on that exact candidate.
Run `./check.sh --verify-candidate HEAD` immediately before acceptance; update
local coverage, tickets, and review evidence, then create, restore-check,
expose, and upload the durability checkpoint before starting SearchTree.
No admissions, new proof axioms, unsafe substitutions, or native proof
shortcuts are permitted. This planning assignment starts no separate
implementation/review loop and establishes no new validation result.
