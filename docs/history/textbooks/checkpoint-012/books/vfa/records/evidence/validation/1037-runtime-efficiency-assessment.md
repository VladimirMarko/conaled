# Bounded runtime efficiency assessment

The native advisor inspected retained runtime probes, current logs and pinned
checker/Lake source read-only. No further already-reviewed runtime/compiler
setting is established as a material speedup for this full candidate. Current
runtime and resource settings remain unchanged during all formal gates.

The accepted efficiency is normal managed-output reuse: fresh success, unchanged
non-repairing collector, then guarded validation establish their separate evidence.
The prescribed no-cache rehashed +ProofAudit prerequisite should then compile only
the missing managed audit module and reuse ordinary outputs. Replayed diagnostics
or sidecar timestamps alone do not establish actual recompilation. Unexpected
ordinary rebuilding needs the retained incident response and renewed full guard.

Fresh outputs are intentionally private temporary products. Copying them into
managed cache is not an accepted shortcut. Legacy-j1 is an accepted operational
fallback, not a proven whole-project speedup; changing routes needs a new baseline.
Retained j1/j4/mmap probes were inconclusive for whole-run performance, and the
mmap prototype was not adopted. No new experiment or input change occurred.

The 671-selector acquisition already avoids 5,100 unused Mathlib families while
providing all 3,931 required dependency modules. This is a supported acquisition
and storage improvement, not a measured full-build timing claim.
