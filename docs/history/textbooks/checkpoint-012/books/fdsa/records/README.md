# Retained FDSA mathematics and evidence

The unified checkpoint entrypoint and current book state own continuation instructions.
All instructions, process holds, setup commands and ticket statuses inside these
retained source-session records are historical evidence, not commands to resume
a former host. The mathematical scope and original review obligations survive.

- `math/`: unique loose Lean drafts, formal patches and paper development.
- `research/`: source identities, coverage obligations and expanded references.
- `evidence/`: reviews, actual validation records and compact operational summaries.
- `history/`: inactive control, setup and receipt records.

Committed source/history and the pinned native kit are stored once for the three
books. RETENTION.json resolves original fdsa-control paths to exact files, Git
blobs, common-kit paths or verified byte ranges. Use that resolver for historical
relative links; old absolute scratch paths and session identifiers are inactive.

All 280 original .lean entries (241 distinct contents), six staged Lean variants,
two compressed paper drafts and every AFP archive member remain recoverable.
All exact and alias records were reconstructed and hash checked. No Lean build,
statement modification, acceptance upgrade or integration occurred. Repeated
checkpoint self-inventories, regenerable outputs and partial setup fragments
were removed or summarized without discarding mathematical source.
