## Architecture, generality and complete mathematical source assessment

**XT01-01 — ordinary branching fold.** `Trees.fold` uses the actual existing `BinaryTree α` constructors, with an explicit empty summary and a callback receiving the left summary, node label and right summary in that order. Empty trees require no inhabitant of the label or summary type. Label and summary universes remain independent. The constructor equations expose the actual recursion; `fold_map` permits any label function, including noninjective ones. `fold_fusion` states the needed empty compatibility and universally quantified callback compatibility explicitly, then proves transport by structural induction. It introduces no bespoke carrier, fold framework, algebra class or extra equality, ordering, monoid or balance assumption. The count and height specializations agree with Mathlib's canonical `numNodes` and `height`, using addition and `max` in their respective node equations; they do not substitute `sizeOf` or conflate shape with inorder content.

**XT01-02 — inorder and shape compatibility.** `Trees.inorder` is the fold with `[]` and `left ++ (label :: right)`. Its constructor, length and map laws preserve node occurrence order. `inorder_length` connects the exact sequence to canonical node count. The three shape-map laws preserve node count, leaf count and height for arbitrary label maps; the leaf proof uses the actual Mathlib `numLeaves_eq_numNodes_succ` relationship. No injectivity or distinct-label assumption is inserted. These are unconditional structural facts, not balance or search-tree properties. `fold_map` also supports the example's general erased-fold observation without assuming cache validity.

**XT01-03 — recursive cache invariant.** `Trees.Cached.erase` is the actual map by `Prod.fst`; `read` returns the explicit empty summary or the stored root annotation; `smartNode` retains both supplied children and computes its stored root from their actual reads. The erasure and reader equations expose those operations directly. `Valid` requires recursively valid children and equality of the stored root with the callback applied to their reads. `smartNode_valid_iff` is the exact conjunction of child validity, so a freshly correct root does not certify or repair bad descendants. `read_eq_fold` uses recursive validity to relate the actual root reader to the independent fold over the erased tree; its proof uses the child induction hypotheses and the local stored equation, without defining correctness circularly. Inorder, node-count, leaf-count and height erasure laws remain unconditional even for invalid caches.

**XT01-04 — ordinary bottom-up annotation.** `annotate` is an ordinary `Trees.fold` whose callback is `smartNode`, not a second recursion or a hidden implementation that assumes the desired theorem. The nil and node equations, recursive validity, erasure back to the input tree, and equality of the resulting read with the original fold are distinct public statements. Their proofs compose the already exposed fold and smart-node contracts. The source handles arbitrary labels, summaries, explicit bases and callbacks; neither cache validity nor an inhabitance assumption is supplied by a new typeclass. The annotation computation is a value construction here; its complete runtime is not claimed or silently included in the later local node-cost model.

**XT01-05 — measured local operations.** `Resources.TreeCache.readRun` returns the actual reader value at cost one. `nodeRun` actually sequences two such reads, invokes the supplied measured callback once on those returned values, retains both child trees, and adds the entry tick using the existing `Resources.bind`, `pure` and `CallCount.tick` interfaces. It does not substitute a caller-provided cost number or traverse the children to manufacture the result. `nodeRun_value` requires the callback's value contract only at the arguments reached by this execution. `nodeRun_cost` exposes the exact reached callback cost plus three without a cache-validity or value-contract premise; `nodeRun_le` separately assumes that reached cost is at most `K` and derives at most `K + 3`. `nodeRun_valid` separately adds both child-validity hypotheses and the reached value contract, then uses the pure smart-node invariant. The decomposition keeps semantic validity, exact measured work and an external callback budget distinct.

The local tariff is the two positive reader calls plus the node-entry tick, with pair construction, projection and the explicitly pure arithmetic callbacks inlined. It is a stated Nat call-count interpretation, not a claim about physical allocation, arbitrary arithmetic bit complexity, or every source program's tariff. No callback-independent constant bound is asserted. Existing leftist-queue helpers use a different zero-cost convention, and a leftist smart constructor can exchange children: neither this positive helper tariff nor fixed inorder preservation is transferred to that algorithm. Full fold/annotation traversal costs and the book's literal two-append inorder evaluation remain outside this frozen bounded unit.
