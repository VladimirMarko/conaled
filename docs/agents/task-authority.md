# Task authority and capability

Requests originating from Vladimir Marko carry standing authorization to finish
the requested deliverable, including committing, integrating into `master`,
pushing `master`, and related issue maintenance, unless the request limits that
authority. Delegations and continuations inherit the originating request's scope
and restrictions. Assignment of an issue commissioned by Vladimir Marko can
establish that provenance; merely discovering an issue cannot. Git identity,
credentials and repository access do not establish who commissioned the work.

For other requests, use only explicitly established publication authority,
including authority to commit. If provenance is unclear, continue useful local
work and leave publication pending until authority is established. Follow
[completion and publication](completion.md) within that mandate and the
[tracker guide](issue-tracker.md) for related issue maintenance.

Use GPT-6-Astra at medium or higher reasoning effort. Other models require
explicit approval from Vladimir Marko. This requirement applies uniformly across
tasks to the primary agent and every delegated agent, including reviewers.
Verify the model and reasoning configuration before undertaking or delegating
work. If an approved configuration is unavailable or cannot be verified, report
the mismatch before proceeding with covered work; reading this policy and
explaining the mismatch remain allowed.

The repository's purpose guides proposals to revise this policy. It does not
authorize an agent to bypass it.
