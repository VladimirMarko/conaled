# Independent assessment: alternatives and generality for #488

Retain WebAssembly Core 2.0, a memory-free straight-line subset, ordered multi-value products, and explicit state. For the first delivery, use native Lean rules tied individually to the pinned standard, prove source preservation into those rules, and expose a separate conditional artifact theorem. A small tested trusted encoder is a defensible first endpoint under the issue's stated alternatives. It must remain visible in the theorem premises and acceptance record. Do not describe that endpoint as verified serialization. Keep the serializer/checker seam replaceable without changing ordinary compiler clients.

This recommendation concerns proof boundaries within the selected Wasm target. It does not reopen LLVM or adopt #489. The comparison supports proceeding with a bounded implementation after the owner settles the trust contract; it does not complete #488.

## Evidence for retaining the proposal

At accepted code `e88e83b5b3a6a1cce08f446469187ab40017870c`, the cartesian interfaces already separate operations from preservation. `FirstOrder.Target`/`Sound` and `Circuit.interpret_compile` permit a new implementation to reuse source composition. `Circuit.execute_correct` connects executable circuit values to the existing digital interpretation. `StackMachine.Certified` retains arbitrary-tail correctness, a useful proof pattern for Wasm stack contexts. No universal new IR is necessary. The selected files have no diff from preparation revision `d1a1a048` to this accepted snapshot.

`FiniteSumLowering.lower_correct` already handles open contexts, binders and nested sums, while `caseCircuit_work` explicitly charges both arms. `Indefinite.Program.transport` accepts input, state and output relations with initialization and one-step simulation, then derives stream observations. That is enough of a consumer interface for explicit-state Wasm; a new engine or scheduler contract need not infect source compilation. Its `transport_bound` explicitly leaves target transition work and temporary space to the backend.

Core 2's function typing accepts result sequences, fitting unit as empty and products as concatenation. Straight-line bodies can return several values without using multi-value structured branches. Avoiding memory keeps aliasing, pointer provenance and heap serialization outside this fragment. This is a generality advantage for existing product clients, not a claim that every finite product fits every runtime's practical limits. [Pinned Core 2 type rules](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/document/core/valid/types.rst).

## Compare the artifact endpoints

| Endpoint | What must be proved | Remaining trust and practical consequence |
|---|---|---|
| Standard-rule target plus trusted encoding | Compilation preserves source values under standard subset execution; generated module validates; accepted inputs terminate without traps; ABI encoders/decoders preserve representations | The emitted bytes must decode to that module. A pinned printer plus WABT assembler is an explicit external premise, as are file identity, runtime conformance and host marshalling. Useful first delivery, with actual artifact execution and negative tests. |
| Verified serializer | Every successful serialization satisfies the selected standard binary grammar and denotes the proved module | A parser implementation is not essential if a grammar relation is formalized directly. Need section lengths/order, indices, vectors, opcode immediates and signed/unsigned LEB obligations. The bytes loaded must still equal the proved output; Lean extraction/runtime and Wasm engine are separate assumptions. Stronger endpoint, with bounded but real additional work. |
| Sound translation validation | Acceptance of the actual artifact establishes its typed source semantics, with exact source, ABI and module identity | A checker over an AST does not remove parser trust. An unverified parser can misread precisely the bytes being validated. A proved decoder or independently justified byte-to-AST relation is required to remove that premise. Optimizing/untrusted producers become possible without proving each producer. |

For this first deterministic lowering, structural checking of decoded output against the proved target is simpler than semantic validation of arbitrary rewrites. It detects changed instructions or output order, but keeps the parser premise. This is an incremental improvement over a trusted assembler, not automatically a smaller total trusted base. If producer diversity or optimizations become important, a sound validator with explicit certificates becomes more valuable. A verified serializer and translation validator can coexist; they solve different obligations.

The smallest useful correction is to specify an artifact relation such as `DecodesCore2(bytes, module)`, indexed by the ABI/export and exact source contract. Prove the source-to-module theorem independently. The first artifact theorem may consume that relation as an explicitly trusted premise. Later prove that the serializer produces it, or derive it from a decoder and checker. Do not add one large mandatory certificate record to `FirstOrder.Target` or ordinary Lean clients.

`GraphTranslationValidator.check_sound` is useful local precedent: its conclusion retains the actual declaration, name, primitive environment and source. Its certificate supplies executable instructions rather than a correctness axiom. Its Lean-expression decoder and equality checker do not parse Wasm or establish Wasm semantics. Reuse the obligation pattern, not the implementation as a ready Wasm validator (`SquareKit/Internal/GraphTranslationValidator.lean:33–99`).

## External formalizations versus native subset rules

I inspected exact pinned upstream files, rather than relying on current search summaries.

* **WasmCert-Coq, `58a3d3f8b7af4dc8aa9351f254a9e672643b21f8`:** the README describes Core 2 plus subtyping and tail-call additions, interpreter/type-checker/instantiation results, and an explicitly unverified experimental binary parser. Its checker theorem `b_e_type_checker_reflects_typing` relates checker acceptance to `be_typing`; this is not source-program preservation. `instantiation_sound` assumes a typed store and an instantiation relation and concludes store/frame properties. The pinned license is mostly MIT, with `src/Parray/` LGPL-2.1+. The pinned README mentions CompCert numerics, but does **not** contain the newer moving README's CompCert directory licensing paragraph. Audit actual transitive dependencies before copying or adopting code. [README](https://github.com/WasmCert/WasmCert-Coq/blob/58a3d3f8b7af4dc8aa9351f254a9e672643b21f8/README.md), [checker theorem](https://github.com/WasmCert/WasmCert-Coq/blob/58a3d3f8b7af4dc8aa9351f254a9e672643b21f8/theories/type_checker_reflects_typing.v), [instantiation theorem](https://github.com/WasmCert/WasmCert-Coq/blob/58a3d3f8b7af4dc8aa9351f254a9e672643b21f8/theories/instantiation_sound.v), [license](https://github.com/WasmCert/WasmCert-Coq/blob/58a3d3f8b7af4dc8aa9351f254a9e672643b21f8/LICENSE.txt).
* **WasmCert-Isabelle, `d9b4659c8b38879a5fc7e0213950751a61091908`:** BSD-2-Clause; the README requires Isabelle2025-2 plus AFP and supplies extracted OCaml definitions. The inspected `preservation` theorem preserves configuration typing under a reduction, and `progress` permits values, a trap, or another step. Neither excludes traps or proves termination. A precise audit of the selected Core 2 rules and AFP/dependency revision remains open. [README](https://github.com/WasmCert/WasmCert-Isabelle/blob/d9b4659c8b38879a5fc7e0213950751a61091908/README.md), [soundness theory](https://github.com/WasmCert/WasmCert-Isabelle/blob/d9b4659c8b38879a5fc7e0213950751a61091908/WebAssembly/Wasm_Soundness.thy), [license](https://github.com/WasmCert/WasmCert-Isabelle/blob/d9b4659c8b38879a5fc7e0213950751a61091908/LICENSE).

These are credible semantics references and potential independent execution oracles. Native Lean's advantage here is direct composition with the existing checked client theorems and audit, not that foreign foundations are intrinsically weaker. External reuse could avoid redoing broad semantics when control, memory or more instructions are added. It requires an explicit story for importing results, translating proofs, or trusting a foreign theorem checker and its cross-language interface. No such checked bridge was found in the inspected local interfaces. An external theorem cited in a Lean comment does not discharge a Lean preservation premise.

For the bounded first subset, mechanize standard configurations, typing and selected reductions, with a rule correspondence table and explicit subset embedding. Merely calling a circuit-like evaluator “Wasm” would leave the decisive connection missing. If the receiving standard semantics is itself locally mechanized, its faithfulness to the published standard remains a specification-review boundary even after proving the embedding. A full cross-prover bridge is unnecessary to state this honestly.

The official pinned source separates W3C document licensing from Apache-2.0 interpreter and test licensing; preserve applicable notices if definitions or tests are copied. [Core 2 license map](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/LICENSE).

## Supported gaps, risks and open questions

**Established from inspected code:** the relevant circuit layer has Boolean gates, while `FirstOrder` parameterizes its base carrier. `Adders.fullAdder_addition` proves a one-bit sum/carry equation; it is not a word32 modulo-addition backend. The proposed word bridge still needs development. `Stack.Staging`'s Int specialization cannot silently become modular machine arithmetic. `Circuit.Equivalent` includes complete digital behavior, so value-only Wasm lowering must not claim preservation of rational signal timing. Existing circuit work/arena and stack instruction counts are not engine storage or latency bounds.

**Established representation distinction:** `FiniteSum.Valid` requires `encode (observe bits) = bits`, including zero inactive payload. Lean Bool has no invalid numeric tag; a Wasm adapter therefore owes the extra i32 0/1 check before invoking that native decoder. General Wasm truthiness is too permissive for this ABI. A valid Wasm module can still receive or produce a noncanonical source encoding.

**Risk, not an observed defect:** a version/default mismatch could enable instructions beyond the proved fragment. WABT 1.0.41 and Wasmtime 45.0.2 source snapshots support multi-value, but no execution was performed here. Use a positive opcode/module-feature admission check in addition to runtime feature controls. Different host limits can reject a mathematically well-typed large product. Classify that as resource/admission failure without adding an arbitrary 64-bit semantic cap.

**Open:** native word primitives versus Boolean ripple lowering should be compared with a tiny implementation/proof trial. The former gives direct modular arithmetic but needs a carrier/codec route alongside Boolean circuits; the latter reuses current finite-sum lowering but expands values and work. Neither is proved cheaper from present evidence. Keep their common observations and ABI relations fixed during comparison.

Explicit state helps portability because the value consists of canonical data rather than engine references. It does not establish live migration: schema/version agreement, state decoding, program correspondence, in-flight effects and handoff still need contracts. For this pure step fragment, retaining the returned state across fresh instances is semantically sufficient; one retained instance is a useful implementation test, not a theorem premise that should be imposed on portable explicit-state semantics.

## Discriminating checks

1. **Word and width:** proposed pure oracle `s=(x+y) mod 2^32`, `z=x xor y`, output `(s,z, if tag then z else s)`. With `x=0xffffffff`, `y=1`, it returns `(0,0xfffffffe,0)` for false and `(0,0xfffffffe,0xfffffffe)` for true. Three words represent 96 source bits. Test carry chains, each bit position and asymmetric outputs. A checked BitVec theorem plus a codec bridge would exclude arithmetic/truncation errors universally; sample external runs only exercise the encoder/runtime path on those cases.
2. **Nested sums:** use actual `FiniteSum.Term.caseE` with distinct branch results. Reject numeric tag 2, and canonical tags with nonzero inactive payload, including nested inactive tags. Test that failure occurs before transition/state update. Native `decode_iff` supplies the canonical-value characterization; adapter correctness must connect machine integers to it.
3. **Retained state:** the inspected `Program.delay` and `seq` give transition `(x,(s,t)) ↦ (t,(x,s))`. From `(false,false)`, inputs `[true,false,true]` give outputs `[false,false,true]` and final state `(true,false)`. Compare every state, not just final output. Swapped state slots and resetting on each call are distinct negative variants. These values were derived from the definitions, not executed in Lean during this pass.
4. **Actual artifact binding:** mutate a valid constant/opcode, export index, output order or ABI version and ensure the source-bound checker rejects it or the runtime comparison detects it. Separately test truncated sections, excessive LEB length, unsupported features and bad arity. Ordinary engine validation can accept a semantically changed but well-typed module. Conversely, a byte change can preserve semantics: Core 2 permits some nonminimal LEB encodings. Do not demand rejection of every changed byte unless the contract intentionally requires exact byte identity. [Pinned binary integer rules](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/document/core/binary/values.rst).
5. **Termination and resource separation:** prove the admitted straight-line fragment terminates without trap under valid representations, and reject division/unsupported operations before emission. Test externally imposed resource/fuel failure separately. Type safety alone does not make a total-source execution theorem.
