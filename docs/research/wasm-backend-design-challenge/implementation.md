# Independent assessment: implementation and use

Recommend retaining the memory-free Core 2.0, ordered multi-value proposal, with a staged artifact contract. The first delivery should prove the admitted source fragment against a documented embedding into selected standard Wasm rules and explicitly trust a pinned encoding path. It must also emit and execute real bytes. Keep byte correspondence as a separate relation so a later verified serializer or sound byte-facing validator can discharge that premise without changing source clients. This is a recommendation, not adoption of the trust boundary.

The strongest evidence for retention is existing compositional code: `Circuit.interpret` and `interpret_compile` already fold circuits into any `FirstOrderCompiler.Target Gate`; `FiniteSum.lower_correct` covers open contexts and nested sums; `Indefinite.Program.body` is already an input/state-to-output/state circuit. None requires a scheduler, universal compiler IR, or #489 evidence architecture. Core 2 function types support sequences of results, which fit the existing product structure without a 64-bit packing restriction ([pinned type rules](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/document/core/valid/types.rst)).

## Reuse and author obligations

All repository code references below are relative to accepted commit `e88e83b5b3a6a1cce08f446469187ab40017870c`. I inspected the named files in the checkout and checked that the compiler, circuit, stack, adder and finite-sum/indefinite files have no differences from that commit. No builds were run.

| Route | Existing evidence | New work and caller consequences |
|---|---|---|
| Circuit to Wasm | `Applications/Circuits/Syntax.lean:47,66`, `Execution.lean:19,28`, `Correctness.lean:70,80` | Supply a target with local allocation and code composition, then prove actual standard-rule execution realizes its denotation. Existing circuit and finite-sum callers retain their APIs. Gate delay metadata is irrelevant to Boolean execution; do not claim preservation of analog timing. |
| Direct first-order word target | `FirstOrder.lean:67,91,119,138` separates operations, semantic laws and frontend theorem | Instantiate an explicit fixed-width carrier/primitive meaning and prove modulo arithmetic. This can use native i32 operations, but needs an adapter to the existing Boolean finite-sum/circuit clients. One ground carrier does not automatically supply distinct Boolean and word sorts. |

Prefer the circuit route as the initial reusable implementation, unless a bounded comparison shows that the word bridge costs more than a direct word target plus codecs. The acceptance criterion is a checked word-level statement and a composed finite-selector client whichever route wins. The current full-adder proves one-bit arithmetic (`Applications/Timing/Adders.lean:61`); it does not already prove ripple addition over BitVec 32. A circuit implementation must build that theorem. A direct word implementation must not present a separate word demo and unrelated Boolean selector as the required composed client.

For backend authors, put flattening, local allocation/renaming, preserved operand-stack tails, and local-store noninterference in the reusable backend. Callers should provide a supported typed source term or circuit, a source-level specification when needed, and typed inputs. They should not prove local indices or serialized section lengths on each use. Reuse `FirstOrder.compile_sound` only after connecting `Sound.denote` to operational execution: defining denotation as the desired source function makes the local square easy but proves nothing about emitted instructions. `Compiler.lean` includes functions/application beyond this bounded route; do not advertise the whole compiler as supported.

## Obligations that must stay separate

The proposed contract should expose these facts, with proofs or explicitly named premises:

1. **Admitted source and ABI.** Unit is empty; products concatenate left before right; Boolean leaves are i32 0 or 1. Prove executable encode/decode roundtrip, decoder rejection, and output validity. Source contexts need care: `FirstOrder.context (a :: Γ)` is `(context Γ, a)`, so simply flattening the list head first reverses the established environment order. State uses input followed by old state and output followed by new state. Fixed-word bit order and signed host presentation must be specified separately.
2. **Target execution.** The generated module validates in the selected standard subset; invoking its named export on encoded admitted inputs terminates with exactly the encoded source result and cannot trap. Prove instruction-sequence composition under surrounding operand stacks and unaffected locals. Include module typing, export lookup, instantiation and invocation, not only an instruction evaluator. The standard explicitly separates these module operations ([pinned module execution](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/document/core/exec/modules.rst)).
3. **Artifact correspondence.** Relate this exact byte buffer to that module, ABI version and export. An initial theorem may assume this relation, with the pinned encoder/assembler as the identified trusted producer and independent tests as evidence. Do not represent the assumption as an axiom established by tool success. Section lengths, function/code correspondence and indices are real binary-format work ([pinned binary modules](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/document/core/binary/modules.rst)).
4. **External execution.** State explicitly the assumption that the configured engine implements the selected semantics and the host faithfully marshals values and carries state. Fuel, compilation/resource rejection and host failure are separate external outcomes. Mathematical termination does not guarantee that a finite host budget succeeds. Feature flags and a subset check must reject features outside the theorem even when the engine accepts them.

The existing `GraphTranslationValidator.check_sound` (`SquareKit/Internal/GraphTranslationValidator.lean:75`) provides a useful pattern: acceptance is indexed by source, actual artifact and environment, with a proved checker implication. Its certificate/checker operate on Lean declarations; they are not a Wasm semantic validator. A new validator over a parsed AST still trusts the parser-to-byte correspondence. The pinned WasmCert-Coq README explicitly calls its binary parser unverified, so importing that interpreter would not discharge this premise ([README at 58a3d3f8](https://raw.githubusercontent.com/WasmCert/WasmCert-Coq/58a3d3f8b7af4dc8aa9351f254a9e672643b21f8/README.md)). I inspected that claim, not its proof bodies or full license dependency closure; no external framework adoption is recommended here.

`RegionalAdmission.Realization` and `Bounded` (`Applications/FRP/RegionalAdmission.lean:40,55`) separate semantic realization from a bound on a particular execution model. Follow that pattern for #481/#485 rather than attaching Circuit arena bounds to Wasm. Charge local slots, stack depth, emitted instructions, codecs and state transfer in their named models. Such accounting does not prove physical bytes or latency.

## Supported concerns and open risks

**Established gap: invalid external inputs do not exist in the source type.** `FiniteSum.decode` accepts Boolean products and checks inactive payload canonicality. It cannot reject an external tag integer 2 because no such Boolean exists there. First reject noncanonical i32 leaves, then use `FiniteSum.decode`; prove the composed rejection contract. `observe` alone intentionally ignores inactive payloads and is inappropriate as external admission. If rejection lives in the host adapter, say the public admitted entrypoint is that adapter; raw export calls are outside the valid-input theorem. Do not imply the raw module rejects invalid encodings unless it implements checks.

**Established gap: eager finite sums demand total arms.** `FiniteSumLowering.caseCircuit` evaluates both arms, and `caseCircuit_work` charges both. The supported Boolean primitives are total. A future primitive that traps on inactive data would invalidate this reasoning even if the selected arm is safe. Keep total fixed-word add/xor/select, or prove a new lazy control-flow lowering. Standard numerical rules distinguish partial operators and traps ([pinned instruction rules](https://raw.githubusercontent.com/WebAssembly/spec/05ca4182176763112561ae20153975c12bd689e4/document/core/exec/instructions.rst)).

**Plausible implementation risk: constant-size mathematical products do not imply manageable code or engine admission.** Recursive circuit syntax can duplicate subcomputations; locals can avoid repeated execution only with a proved compilation strategy. Prototype code size and actual arity/local limits for the word/finite-sum client before promising resource behavior. Expose rejection for target limits instead of changing the source into a 64-bit result type.

**Plausible integration risk: byte identity checked before a file is replaced.** Validate and execute the same immutable buffer, or document the stable-file premise. A hash receipt alone does not connect two different reads. Wrong export selection and reordered results can preserve Wasm validation while breaking the source result.

## Discriminating acceptance evidence

The following are proposed tests and proofs, not completed validation.

| Fixture | Required comparison and separating failure |
|---|---|
| Pure composed word/finite-selector program | Freeze a source function returning three Word32 results, e.g. modular sum, xor and a finite-selected input. At x=0xffffffff, y=1, expect sum=0 and xor=0xfffffffe, with selected word depending on the branch. This proposed oracle follows modular arithmetic; instantiate and prove it against the selected source definition before testing. Three words exercise 96 result bits. Include zero, highest bit and carry chains; a full-adder truth table alone is insufficient. |
| Nested sums | Compile actual `FiniteSum.Term` cases; test both arms, nested tags and branch-dependent payloads. Reject integer tags outside 0/1 before Boolean decoding, and reject nonzero inactive payloads even when all leaves are canonical Booleans. Test nested inactive sums too. |
| Native two-delay program | `Indefinite.Program.delay` maps (input,state) to (state,input); `seq` stores (first state,second state). From (false,false), inputs true,false,true yield outputs false,false,true and states (true,false), (false,true), (true,false). This is a manual reduction of inspected constructors, not a newly executed Lean check. Assert every intermediate state as well as final state. Resetting state each call yields the wrong third output. |
| ABI composition | Combine unit, nested products and distinct outputs/state values. Deliberately swap output/state or context components and require a mismatch. Equal-valued fixtures cannot detect permutation bugs. |
| Artifact identity and negative loading | Malformed section length must fail parsing; unsupported instructions/features must fail subset admission. A changed constant or wrong but well-typed export can pass runtime validation, so require semantic mismatch or byte/AST correspondence failure. Do not require all byte mutations to be semantically different: a custom-section change may preserve meaning. |
| Host and resource failure | Exercise missing/excess arguments, noncanonical booleans and incorrect result arity; force a declared resource/admission failure without classifying it as source falsity. Test the pinned host binding's unsigned word conversion and full multi-value ordering. |

Use one loaded instance for the retained-state demonstration, with a host-owned explicit state buffer. Because the proposed module has no hidden mutable state, re-instantiating while faithfully passing returned state is semantically equivalent; instance continuity alone does not test retention. The decisive invariant is the state fed into the next invocation. Likewise, result equality for a few inputs does not establish the all-input preservation theorem or encoder correctness.

Implement in dependency order: freeze the admitted fragment and ABI; prove codecs and target operations; compose the frontend and state-step theorems; establish module validation/invocation; identify the encoding premise; emit/parse/execute the exact artifacts; run formal acceptance and independent review. A verified serializer can later prove grammar correspondence directly, or a sound validator can accept alternative artifacts, without imposing either architecture on direct clients now.

## Independence and limits

I had no prior involvement in this challenge and received the shared brief plus repository context. I did not read another assessment or coordinate conclusions. Evidence consists of source inspection, a no-difference Git comparison for the main compiler/client files, the retained tool-source material and pinned primary specifications. WABT 1.0.41 and Wasmtime 45.0.2 are candidate tool pins, not runtimes exercised here. No packages were installed, no artifact was emitted, no new proof was checked, and no engine or full external-mechanization audit was performed. Concurrent verification-tooling edits were excluded. The recommended boundary remains conditional on owner acceptance of explicitly trusted serialization.
