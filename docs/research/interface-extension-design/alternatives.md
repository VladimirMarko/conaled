# #704 independent assessment: alternatives and generality

Recommendation: adopt the bounded raw transformation layer and its quotient adapter; retain Mathlib functor categories for equality-lawful clients; retain the existing Span strong-transformation/modification presentation. Defer a universal displayed-category interface. ## Raw transformations and the lawful alternative

The strongest reason to retain separate raw data and semantic laws is an existing mathematical distinction, not local naming precedent. `SquareKit/Category.lean` defines `CategoryOps`, `HomEquiv`, `CategoryCongr`, and `CategoryLaws` separately. `SquareKit/CategoryMap.lean:16` defines object/arrow data without laws, and `MapLaws` separately supplies congruence and identity/composition preservation. `RawMap.quotientFunctor` at line 85 needs both categories' congruence and laws plus the map laws. `RawMap.toFunctor` at line 103 already supplies the equality-lawful specialization.

Mathlib's pinned `Mathlib/CategoryTheory/NatTrans.lean:54` defines natural transformations between actual functors, with equality-valued naturality; `Functor/Category.lean:53` builds their category. This is an appropriate destination and a useful direct entry point when callers already have category instances. It cannot preserve the raw operations of the proposed Nat × Bool example while imposing equality category laws. NAND composition fails associativity independently of the natural-number coordinate. Passing to equality of Nat coordinates repairs category laws by forgetting Bool. The adapter therefore changes the arrow observation while retaining objects, rather than proving equality laws for the original operations.

The proposed componentwise target relation is exactly the observation compatible with that repair. For fixed raw maps F and G satisfying the quotientFunctor hypotheses, equality of the descended natural transformations should be equivalent to target equivalence of every component. The existing `HomQuotient.mk_eq_iff` supplies the component argument and `NatTrans.ext` supplies transformation extensionality. This statement does not recover raw representatives and does not assert a categorical equivalence for varying raw maps. Keep the latter scope with #706.

The brief's minimal assumptions are credible on paper: identity naturality uses target units; composition uses target associativity and congruence; precomposition substitutes arrows into naturality; postcomposition needs congruence and composition preservation for the postmap. For transformations between arbitrary RawMaps, precomposition should remain available even when the premap has no MapLaws. A generic definition using bundled functors would silently strengthen that contract. A hybrid that uses raw components first and descends only at the adapter meets both needs.

The new example should check a nonzero Nat component, composition from 1 to 2, failure of equality associativity, and distinct Bool components with equal images. Those observations test more than an identity-only example. The existing `Examples/WitnessEquivalence.lean:11–25` is an independent control: NAND there composes witnesses, whereas the new example composes raw arrows. Its `squares_distinct` and `erased_squares_equal` at lines 51–57 establish actual witness erasure. Keep these roles distinct. Neither example says that ordinary Prop naturality contains recoverable higher witness data.

Smallest useful refinement: specify the quotient comparison with fixed F and G and their laws, and supply an equality-lawful application that agrees with ordinary Mathlib NatTrans identity/composition. This tests reuse of the standard interface without requiring new functor-category packaging. Do not demand equality associativity of raw transformation components; the planned semantic relation is the appropriate law.

## What full subcategories do and do not express

Mathlib's `CategoryTheory/ObjectProperty/FullSubcategory.lean` defines objects as an object with a property and inherits every ambient morphism via `InducedCategory`. Its `homMk` admits any ambient arrow. This makes a full subcategory suitable for adding a property when all ambient arrows between qualifying objects remain intended arrows.

There are two levels here that the comparison must distinguish:

* A full subcategory of categories selected for having terminal objects still admits functors that fail to preserve terminal objects. It does not describe categories with terminal-preserving maps.
* A full subcategory of a fixed functor category, selected by a preservation property on functors, does restrict which functors occur as objects. It retains all natural transformations between those functors. This can be exactly right if the intended transformations have no extra compatibility requirement, or that requirement follows from naturality and the relevant universal properties.

Consequently, operation preservation does not by itself refute every full-subcategory presentation. State the ambient category and the dimension at which morphisms are restricted. The terminal counterexample distinguishes the first construction; it does not refute the second.

The repository contains substantive preservation contracts. `SquareKit/CartesianMap.lean` gives comparison-arrow data through `Comparison`, `TerminalMap`, and `ProductMap`, inverse equations through `ComparisonLaws`, and operation compatibility through `TerminalMapLaws` and `ProductMapLaws`. The composition and transport theorems consume these fields. They are not mere properties of the underlying categories. `Examples/CategoryMaps.lean` derives preservation of Mathlib products and the empty-diagram limit from the raw evaluation comparison and law inputs. This is evidence for retaining the operation interface and adapter.

The separating map is `Over.forget Bool`. `Examples/MatesBaseChange.lean:85` proves `forget_not_leftExact` by showing that the image of the terminal display is Bool and has two distinct maps from Unit. It is admitted by the pullback-preserving Span construction (`Examples/SpanInterpretation.lean:70–74`). Thus the established examples distinguish pullback-preserving interpretations from terminal-preserving interpretations even though their source and target support the relevant objects. This is a real restriction on admissible interpretation maps. The proof is stated as failure of finite-limit preservation, with terminal failure as its decisive argument; it is not literally a theorem quantifying over every raw TerminalMap package.

Do not infer from those data fields that all lawful Cartesian comparisons represent independent choices at the semantic observation. Universal properties may determine comparison arrows modulo the target relation. Conversely, arbitrary raw operations without the universal laws do not justify such uniqueness. The smallest correction is explanatory: separate unrestricted raw comparison data, lawful comparisons determined semantically, and witness-valued refinements whose evidence may remain distinguishable.

## Displayed structures and the Span route

A category of structures is a plausible mathematical organization when objects carry operations and maps must preserve them. A displayed formulation can express a structure over each base object and admissible structured arrows over base arrows, with identity/composition closure. This is an alternative organization of the data and laws, not a way to derive the preservation obligations for free. The present task has no demonstrated need for one generic displayed implementation across all structures.

There is already relevant generic machinery: `SquareKit/MorphismRestriction.lean` stores an arrow and a Type-valued admissibility witness, asks for identity/composition closure, and transports semantic category laws through the forget map. Its induced relation deliberately ignores the witness. This supplies a concrete category-of-structures pattern at the raw level, while also making its information-loss contract explicit. It should be acknowledged before proposing a new generic framework.

For Span, the supplied presentation already carries the additional dimension needed by its clients. `SquareKit/SpanInterpretationComposition.lean` constructs `composeTransformations` from vertical composition and precomposition, `compositionModification` from the full slice comparison, and `composeModifications` by whiskering. `composition_associativity` and the unit results compare those data with independently supplied associator/unitor maps. `Examples/SpanInterpretationComposition.lean` applies these comparisons to the dependent payload and apex (3,true) under three nonidentity forgetful functors. The selected payload and apex theorems use projection preservation in addition to an inverse/forward round trip. This is enough evidence to retain the existing structured route under its original pullback-preservation hypotheses.

The truncation control is also relevant: `Examples/SpanInterpretation.lean:78–107` constructs a target pullback inhabitant while the source pullback is empty and derives failure of pullback preservation. Thus a lawful functor alone does not supply the Span comparison isomorphism. Replacing pullback preservation with finite-limit preservation would lose the admitted forgetful example; dropping preservation would admit truncation and invalidate the comparison contract.

One comparison remains underspecified: “erasing selected comparison data.” The canonical Span comparison is constructed from F, chosen pullbacks and their universal properties. Forgetting its explicit field while retaining all those inputs can permit reconstruction. The selected-client theorems establish preservation by the current comparison; they do not prove that every less explicitly packaged representation loses that information. A loss claim needs a defined erasure map and a pair of distinct inputs with equal images, or a theorem identifying exactly what is reconstructible. The independent witness erasure example establishes that loss for WitnessComma, not automatically for canonical Span comparison data.

Smallest useful correction: name each proposed projection. If it keeps F and the original chosen pullbacks, assess reconstruction using `actionIso` and the existing modification constructors. If it retains only base-object images or isomorphism classes, exhibit the missing arrow action or comparison explicitly. Do not add arbitrary comparison choices merely to manufacture noninjectivity; that would change the client contract.

## Decisions and acceptance evidence

Adopt A for ordinary transformations modulo target HomEquiv, subject to checked minimal hypotheses and quotient identity/composition laws. Adopt B as a specialization and quotient destination. Reject B only as a replacement requiring equality laws on every original raw operation. Retain full subcategories for genuine object properties and for selected functors when all intended natural transformations are admissible. Retain C's existing explicit structured maps and Span transformations/modifications; defer a universal displayed-category implementation pending a consumer that removes repeated obligations across these examples.

Before accepting stronger claims, check these discriminators:

1. Raw NAND example: semantic laws and nontrivial transformation composition pass, equality associativity fails, and distinct components descend equally.
2. Hypothesis boundary: prewhiskering a natural transformation by a raw map without MapLaws is available; postwhiskering uses the postmap's preservation assumptions.
3. Full-subcategory boundary: state the ambient category. Retain the forgetful functor as pullback preserving and show why terminal preservation is unavailable. Do not attribute that failure to all full subcategories of functor categories.
4. Structured recovery: define any Span erasure before claiming it prevents recovery. Reuse the complete payload/apex, arbitrary slice-arrow action, modification composition, associativity and unit results under their original hypotheses.

These recommendations follow inspected definitions and paper arguments. No new proof, elaboration-cost comparison, author-productivity measurement, or universal equivalence was established in this assessment. The brief's candidate build, axiom audit and independent acceptance review remain necessary for implementation.
