# Atomic-base support and selected derivation transport

For [#377](https://github.com/VladimirMarko/conaled/issues/377), implement a bounded
basis-indexed atoms/implication semantics, with an optional labelled-tree layer.
The construction below proves persistence and implication introduction/application
on paper. It supplies a trace-preserving inclusion bridge, rejects recovery of
an arbitrary selected trace from support, and repairs a changed inference rule.
No new Lean theorem or runtime result is claimed. The implementation successor
should formalize these contracts independently of the existing engine.

This resolves the support proposal in
[deferred-traditions-reassessment.md](deferred-traditions-reassessment.md).
The [coverage map](semantic-traditions-coverage.md) previously made an independent
selected-witness bridge part of the promotion condition. That condition is
appropriate for a selected-witness client. Requiring it of every support client
would discard the separate capability demonstrated here: a specification can
state an inferential requirement over future extensions without choosing a proof.

The finite Horn restriction and structural recursive presentation are our frozen
specification. We do not inherit a full second-order completeness theorem or use
the questionable derived disjunction display. Labels, premise order, selected
proofs and traces are separate local data, not claims about source support.

Fix a set `Atom`. A rule is `(S,c)`, where `S` is a finite set of atoms and
`c : Atom`; write `S ⇒ c`. A base `B` is a finite set of such rules.
`Derivable(B,c)` means that there is a finite rooted tree whose root concludes
`c`, whose nodes use rules in `B`, and whose children prove every premise of
the rule at that node. Empty-premise rules are leaves. Cycles without a leaf
supply no finite derivation. No atom is an implicit assumption.

A basis `K` is any set of these finite bases. Throughout a support judgment,
`B ∈ K`; write `B ≤K D` for `B,D ∈ K` and `B ⊆ D`. Inclusion is reflexive and
transitive, even if `K` is not closed under union. Formulas are generated by
`atom c` and `A → C`. Define by structural recursion on formulas:

```text
Supp(K,B,atom c) := Derivable(B,c)
Supp(K,B,A → C) := ∀ D ∈ K, B ⊆ D → (Supp(K,D,A) → Supp(K,D,C)).
```

Both recursive calls use smaller formulas; the larger base does not threaten
well-foundedness. For a finite context `Γ`, define a separate abbreviation

```text
Γ ⊨(K,B) C := ∀ D ∈ K, B ⊆ D →
                 ((∀ A ∈ Γ, Supp(K,D,A)) → Supp(K,D,C)).
```

Allowing empty `Γ` here is our extension of the nonempty local consequence
clause. It agrees with `Supp(K,B,C)` by persistence below and reflexivity.

## Persistence and implication laws

**Atomic weakening.** If `B ⊆ D`, copy each finite derivation node, retaining its
rule and child derivations. Each rule remains a member of `D`. Induction on the
tree proves `Derivable(B,c) → Derivable(D,c)`.

**Support persistence.** Fix `K` and `B ≤K D`. Induct on the formula. The atomic
case is weakening. For `A → C`, take `E ∈ K` with `D ⊆ E` and assume
`Supp(K,E,A)`. Transitivity gives `B ⊆ E`, so the implication supported at `B`
supplies `Supp(K,E,C)`. This implication step needs no covariance assumption on
its antecedent: the antecedent is tested at the same `E` in both judgments.

**Introduction.** Suppose `Γ ∪ {A} ⊨(K,B) C`. To prove
`Γ ⊨(K,B) A → C`, take `D ≥K B` supporting every formula of `Γ`, then
`E ≥K D` supporting `A`. Persistence transports each member of `Γ` from `D`
to `E`. Apply the premise at `E`. This proves the implication at `D` and the
claimed consequence at `B`. For empty `Γ`, it yields support of `A → C` at `B`.

**Application.** If `Supp(K,B,A → C)` and `Supp(K,B,A)`, use the implication
clause with `D=B`. More generally, from `Γ ⊨(K,B) A → C` and
`Γ ⊨(K,B) A`, evaluate both at any extension supporting `Γ`, then use that
same-base application. Neither proof assumes soundness of a whole logic.

## Two strict extensions and a changed basis

For this original fixture take `Atom={p,q,r}` and `K` all finite Horn bases on
these atoms. Define

```text
B0 = { {p} ⇒ q }
B1 = B0 ∪ { ∅ ⇒ p }
B2 = B1 ∪ { {q} ⇒ r }.
```

The added rules are distinct, so both inclusions are strict. `B0` derives no
atom: a finite tree must have a leaf, and its only rule requires a premise.
At `B1`, the leaf `∅⇒p` gives `p`; applying `p⇒q` gives `q`. There is no rule
concluding `r`. At `B2`, applying `q⇒r` to that `q` derivation gives `r`.

| Judgment | B0 | B1 | B2 |
|---|---|---|---|
| `p` | false | true | true |
| `q` | false | true | true |
| `r` | false | false | true |
| `p → q` | true | true | true |
| `q → r` | false | false | true |

For `p→q`, any permitted extension retaining `p⇒q` converts a finite proof of
`p` into one of `q`; this proves the entire extension-quantified clause.
For `q→r` at `B0`, use extension `B1`, which derives `q` but not `r`. At `B1`,
use reflexivity. At `B2`, use its rule in every extension. Thus checking only
current atomic facts would miss the distinction between the two implications
at `B0`, where neither antecedent is currently derivable.

Fix instead the empty base `E`. In singleton basis `Ksingle={E}`, neither `p`
nor `q` is derivable and `Supp(Ksingle,E,p→q)` holds vacuously. Enlarge the
*basis* to `Klarge={E,{∅⇒p}}`. Its second base is a permitted extension deriving
`p` but not `q`; therefore `Supp(Klarge,E,p→q)` fails. The current base and
formula did not change. Persistence holds inside one fixed basis, not across
arbitrary changes of basis. Both bases in `Klarge` are still finite Horn bases.

## Selected trees, observations and the exact bridge

Independently specify a labelled presentation `L`: each label names an ordered
list of distinct premises and a conclusion. Erasing labels and order yields
`|L|`, a Horn base. A tree in `Tree(L,c)` records the rule label and one child
per ordered premise. This is data, with node count `size`. Define postorder
observation recursively:

```text
trace(node(label,[t1,…,tn])) = trace(t1) ++ … ++ trace(tn) ++ [label].
```

This observation exists before any transport or selector. Labelled inclusion
`i:L↪M` means every old label retains exactly its premise list and conclusion;
new labels are fresh. Recursively copying the tree defines `map(i,t)`. Induction
on `t` proves conclusion preservation, equal size and
`trace(map(i,t))=trace(t)`. Identity and composite inclusions give identity and
composite maps by the same recursion. Erasing a tree proves atom support.
The bridge commutes: erasing after copying and atomic weakening after erasing
both establish the target atomic judgment. It does not reconstruct the tree.

Label `p⇒q` by `b`, `⇒p` by `a`, and `q⇒r` by `c`. At `L1`, select
`tq=b(a())`, with trace `[a,b]` and size 2. At `L2`, its copied tree still has
trace `[a,b]`; the derived `r` tree `c(b(a()))` has trace `[a,b,c]`.
Now extend `L2` by fresh label `d:⇒q` to `L3`. Copying retains `tq` and its
trace. A minimum-node selector instead chooses `d()`, size 1, trace `[d]`.
It is the unique size-1 proof of `q` here, so tie breaking cannot fix the
mismatch. Support of `q` persists in either case. A shorter-proof selector
need not commute with inclusion.

At the *same* `L3`, erase `b(a())` and `d()` to support of `q`. Suppose a
recovery function using only `(L3,q,Supp(K,|L3|,q))` returned the trace of every
selected input tree. It would have to return both `[a,b]` and `[d]` for the same
truth-valued support fact, a contradiction. In Lean a proof in `Prop` likewise
does not encode distinguishable selected traces. This rejects universal
selection recovery, not finding some proof or a chosen canonical proof.

For exact selected-tree recovery, retain `t : Tree(L,c)` alongside the support
judgment and use `map`. For trace-only recovery, retaining the trace plus evidence
that it is realized suffices existentially; executable reproduction still needs
a tree or a reconstruction procedure. Alternatively restrict admitted trees
so their observations agree, and prove that restriction. Requiring a canonical
selector to commute with inclusion is another sufficient assumption, explicitly
refuted for the shortest-proof policy in this fixture.

## Changed inference rule: failure and repair

Rule addition and rule replacement have different obligations. Adding `q⇒r`
above costs a membership/inclusion proof; previous trees and supported formulas
persist unchanged. The generic copying proof needs no new constructor case.

For a replacement, start from `L1={a:⇒p,b:p⇒q}` and replace `b` by
`b':(p,r)⇒q`, leaving `a`. Call this `Lminus`. Its Horn erasure derives `p` only:
no rule concludes `r`, so no finite tree can apply `b'`. Both `q` and `p→q`
fail at this base. Relabelling the old `b(a())` as `b'(a())` is ill-formed because
one child is missing. Neither support persistence nor labelled inclusion applies.

Repair by adding `e:p⇒r`, obtaining `Lrepair`. Replace every use of old `b(t)`
by `b'(T(t),e(T(t)))` and retain `a()`; recursive `T` translates all old trees.
Here `T(b(a()))=b'(a(),e(a()))`, trace `[a,a,e,b']`, size 4. Its two children
supply the ordered premises `p,r`. Target `p→q` also holds: at every extension,
any proof of `p` first supplies `r` using `e`, then supplies `q` using `b'`.
This is a direct new implication proof, not an application of inclusion.

The repair retains the conclusion but fails the original exact-trace contract.
An admissibility proof for the old rule in the target does not remove this
failure. A client requiring the old trace must keep an old derivation as
provenance, or explicitly change its observation contract and prove a relation
between observations. No claim of arbitrary implication transport along a
closed-derivability map follows: implication also quantifies over extensions,
whose compatibility would require separate hypotheses.

## Same-task comparison and implementation decision

| Obligation | Direct labelled-tree route | Support route |
|---|---|---|
| Initial setup | Rules, finite trees, ordered trace, inclusion map | Rules, atomic derivability, basis, recursive formulas, persistence and implication laws |
| B0 to B1 to B2 | Copy any supplied tree; B0 has none | Preserve `p→q` even at B0; derive newly available atoms |
| Retain chosen q trace | Copy `b(a())` | Add the tree bridge; bare support has no selected trace |
| Add shorter q proof | Old tree remains valid; shortest selection changes | Support remains true; says nothing about reselection |
| Replace b by b' | Supply missing r child; prove trace relation separately | Re-establish p→q from e and b'; no inclusion shortcut |

The support layer adds extension-quantified specifications for formulas, including
hypothetical requirements with no current witness. The direct atomic-tree route
has no formula interpretation unless one adds such a layer. Conversely, support
contributes no stronger selected-tree transport than the direct inclusion map.
The table counts distinct obligations, not author time or measured productivity.
The trace-only client can use direct trees without learning basis semantics;
the inferential-specification client can use support without carrying a tree.
