# Independent alternatives and generality assessment for #705

Recommendation: retain the selected coherent-family total bridge as a bounded interoperability addition. Keep the chosen-pullback, span, structural-display and SplitSheaf interfaces. The selected route has an existing pseudonatural inverse and invertible modifications, so it isolates a reusable missing CoGrothendieck adapter without first reconstructing another family's substitution comparison. This supports this adoption scope; it does not establish that coherent arrow diagrams should become the project's general family representation.

This assessment used the shared selection brief and actual sources in `/tmp/conaled-issue-705`, with Mathlib in `/home/vlad/Code/conaled/.lake/packages/mathlib` at the brief's pinned revision `56a005855ea17e0b0958f73ec801ae140b0a1679`. ## Evidence supporting this selection

`SquareKit/Internal/RepresentableCoherentRecovery.lean:20–145` supplies the strict indexed categories `families` and `diagrams`, the `system` pseudofunctor, the `decoder` and `coder` StrongTrans values, and `classificationUnit` and `classificationCounit` as isomorphisms in the StrongTrans category. In particular, the unit's modification equation uses `recovery_reindex`; the selection is stronger than a collection of unrelated equivalences of fibers.

`SquareKit/Internal/CoherentFamilyClassification.lean:18–79` makes `Code E V` a full subcategory of arrow diagrams. It restricts objects by invertibility of restriction images and retains every natural transformation between admissible objects. Its recovery is derived by mapping the evaluation arrow to the identity view. Its naturality in code morphisms is proved in `recoveryIso`, and arbitrary change of indexing category is covered by `reindex`, `decodeReindex`, and `recovery_reindex` at lines 92–166. The mathematical classification therefore already extends beyond presheaf contexts at this lower level; using presheaf contexts in #705 is a selected application, not an inherent limitation of that classification.

Mathlib's `Mathlib/CategoryTheory/Bicategory/Grothendieck.lean:334–391` already maps StrongTrans values to functors, with strict preservation of the base (`map_comp_forget`) and identity/composition isomorphisms. The inspected namespace ends without an action on modifications. `Mathlib/CategoryTheory/FiberedCategory/Grothendieck.lean:35–79,137–142` supplies canonical cartesian lifts, `IsFibered`, and `HasFibers` for arbitrary contravariant Cat-valued pseudofunctors on a locally discrete base. These facts justify placing the modification adapter at the general CoGrothendieck level and keeping the coherent-family instantiation narrow.

These routes solve related but different recovery problems. SplitSheaf retains a sheaf display and recovers its fibers; structural display categories retain a chosen model's family labels and all its display squares; coherent diagrams classify V-valued functors on element categories. A claim that they are interchangeable would require explicit maps and the appropriate hypotheses. In particular, no construction inspected supplies a display object for arbitrary V merely because V is a category.

The span route additionally retains pushforward behavior and noninvertible apex maps. Restricting it to base substitutions is useful for ordinary fibrations but is a restriction of the input data. Keep the native span API when those 2-cells and pull-push operations are the client observations.

## Mathematical limits and adapter work

The restriction-isomorphism requirement is a mathematical recovery condition. `Examples/CoherentFamilyClassification.lean:85–100` supplies `badData_no_recovery` and `badData_not_coherent`: the unrestricted root-dependent diagram has incompatible values at an arrow and its target identity view. This is a separating model, not just an unsuccessful Lean proof. Preserve it in the acceptance record.

By contrast, the absence of a modification action in the inspected CoGrothendieck namespace is an API gap. It does not justify imposing extra conditions on the selected families or accepting a fiberwise substitute for the required total equivalence. Nor does it justify manually rebuilding the total category's composition laws.

Cartesian preservation should be exposed at the generic adapter level if it follows there without extra assumptions. Inspection of `CoGrothendieck.map` shows that the image of a canonical lift has its original base map and a fiber component given by the StrongTrans naturality isomorphism, after mapping an identity. This suggests the standard comparison to the target canonical lift through an invertible vertical arrow. This is a proposed proof route, not a checked theorem in this assessment. It would apply to any StrongTrans in the same setting and would avoid a coherent-family-specific cartesian argument. Checking that comparison and deriving the claimed cartesian property is sufficient; equality with arbitrary chosen cleavages is neither needed nor promised.

The ordinary base is intentionally locally discrete. The existing StrongTrans values encode substitution coherence but no dependent 2-cell action of a TwoFamily model. The bridge consequently provides no proof of the cubical higher coherence or general decoder-admission claims separated in #700–#703. The scoped exclusions in the brief are consistent with the inspected interfaces.

## Corrections and acceptance evidence

No established design defect requires replacing the selection. The smallest useful refinements are:

1. Make the modification/natural-isomorphism adapter generic over the common base and pseudofunctors. State its base behavior explicitly. Keep the application file focused on plugging in `classificationUnit` and `classificationCounit`.
2. Retain the distinction between a general modification map and a map only for invertible modifications. The selected equivalence needs the latter; if only that narrower adapter is implemented, name and document that scope without claiming full modification functoriality.
3. Expose the canonical-lift comparison or cartesian-preservation theorem with the smallest justified assumptions, preferably for any StrongTrans. Ensure the final theorem covers arbitrary cartesian arrows if that is what the report claims.
4. State the adoption as an additional interoperability presentation. Preserve current direct clients, the arbitrary natural-transformation homs, and the native span/display/SplitSheaf APIs.

The brief's proposed examples discriminate the main risks. Successor then doubling, with the stated ordered composite, checks contravariance rather than only identity substitutions. The twisted `localData` tests nonidentity recovery; `collapse` tests a noninvertible family map. Test their total arrows through the new functors, not merely their old fiberwise facts. Recover the map through the total unit's naturality, check the canonical-lift comparison, and use the total functors' composition laws. The existing negative control already establishes the relevant loss claim without a new counterexample.

Unresolved implementation evidence is limited but material: elaborated universe signatures, the actual modification adapter's naturality proof, assembly of the total equivalence with its vertical unit/counit, and the checked cartesian result. No build or proof audit ran in this assessment. Broader efficiency claims or migration to a common family representation remain unsupported by this bounded case; the named alternatives warrant separate consumer-driven adoption work.
