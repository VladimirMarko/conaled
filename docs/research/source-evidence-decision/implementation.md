## Concrete concerns and smallest corrections

1. **Relation coverage changes the theorem.** Established scope distinction: the Python finite checker at lines 171–186 validates submitted rows, initialization and closure. It proves a simulation on that submitted relation and hence initialized traces, not automatically a universal theorem for the whole graph of the selected decoder. Decoder agreement proves inclusion in that graph, not the reverse inclusion. The current sample contains all sixteen rows; the general acceptance contract must say whether it promises only initialized reachable behavior or every `q < 16`. Smallest correction: require all sixteen decoder rows for the advertised whole-relation local law, and all sixteen pure inputs. Alternatively state the narrower trace theorem explicitly, retaining selected decoder agreement on reached states. This is a proposed checker obligation, not a diagnosed defect in the probe's stated reachable-trace contract.

2. **Typed first-order syntax does not itself select the arithmetic fragment.** `FirstOrder.Term` accepts a parameterized vocabulary; its concrete additive backend deliberately excludes variable multiplication and nonzero constants (`FirstOrder.lean:144–148`). Smallest correction: define the bounded arithmetic primitive signature and semantics, then prove its local backend laws. Do not advertise the existing additive instance as the residue implementation. The generic compiler theorem is reusable once these premises are supplied.

3. **Semantic acceptance and executable fallback have distinct premises.** `probe.py:219–237` checks source support before any baseline selection and checks each input before transition. Preserve that behavior. Missing optimization evidence can leave the supported two-register baseline selected while retaining the diagnostic. An unsupported original source cannot enter a fallback interpreter lacking its semantics. Likewise resource-proof absence should retain a semantic result while declining the requested resource-based selection. `RegionalAdmission.lean:88–106` illustrates this separation, but its `Realization` at lines 39–45 is specifically `Plan Input Bool`, not a ready-made integer relation record.

4. **A new proof must not relabel an existing live state.** Plausible integration risk: replacing coefficient, decoder or layout after admission can leave a running session holding the old representation. Smallest correction: index a session by the accepted executor/representation, and require explicit state conversion with its relation proof for migration. A fresh acceptance receipt alone is insufficient. The existing selection/session pattern is recorded at `docs/research/compiler-evidence-comparison.md:110`.

5. **Quotient equality cannot discharge exact arithmetic bounds.** Established mathematical limit: integers 0 and 16 have the same image modulo 16. Order and exact temporary bounds remain integer obligations. Retain six-bit exact temporaries for the diagnostic contract, or prove the separate four-bit modular realization. Four persistent bits versus eight concerns declared state layout; it gives no total-memory, latency or work result. Sources: `docs/research/mmt-compiler-evidence.md:132–144` and the comparison at lines 150–156.

## Composition, diagnostics and maintenance

Both routes must support the same action on evaluation and simultaneous substitution through integer congruence, `Z/16Z`, and little-endian four-bit values. Prove each interpretation's operation clauses, lift them structurally to terms, and derive composed/direct agreement and pointwise agreement on the selected decoder. `eval_subst` supplies the existing syntax-side law; the arithmetic interpretation and bit realization laws remain builder work. The recorded 1,280 cases are finite diagnostic evidence, not the general theorem (`compiler-evidence-comparison.md:240–277`).

The following acceptance decisions should be common to both adapters: reject stale/wrong source or artifact; reject changed coefficient/modulus unless freshly justified; report unsupported primitives without execution through an unsupported fallback; reject wrong initialization or a missing selected converter; reject a claim that recovers lost integer distinctions; require a proved conversion for changed live representation; stop before a transition with an unmet input premise. Accept changed syntax such as `q+q+q` when its correspondence at the exact new source and artifact is checked. Failed evidence should identify the failed gate and preserve the baseline selection diagnostic. It does not prove the program unimplementable.

Maintenance is shared around primitive semantics, fragment evolution, artifact identity, input enforcement and interpretation laws. Native proofs additionally depend on the source adapter and theorem APIs; finite data additionally depends on format/parser/checker coverage and the size of admitted finite domains. Neither inspected study measures production author effort for both proposed routes. There is no supported productivity ranking.

A non-Lean compiler can produce the same bounded source and artifacts and submit either evidence route to an external Lean checker. Its producer need not be verified if every claimed conclusion follows from independently checked evidence tied to the resulting artifact. Reimplementing the checker itself in another language does not inherit its Lean soundness theorem: use proof replay, a verified refinement/extraction connection, or state the new checker/runtime as an additional trust assumption. Ordinary regression tests alone do not supply that connection. Keep this mechanism choice separate from the source author's contract.

Symbolic polynomial certificates could reduce table generation and support uniform parameter proofs, but still need checker soundness, source binding and separate bound/realization proofs. Theory-indexed publication could organize reusable interpretations, but the retained MMT study explicitly does not check the stateful arithmetic interpretation (`mmt-compiler-evidence.md:19–22,146–180`). A common proof language would need a specific capability unavailable through these bounded adapters before its implementation cost belongs in the first slice. None should be excluded merely because an adapter is currently absent.

The next implementation discriminator is one end-to-end artifact-association vertical slice: an exact original source, native proof and finite data for the same selected objects, successful kernel-checked admission, then deliberate source/helper/artifact mutations and a changed-syntax positive case. This would test the missing boundary and reusable conclusions. It is not required before the owner can choose the bounded dual-route contract, and does not justify reopening general foundation research.
