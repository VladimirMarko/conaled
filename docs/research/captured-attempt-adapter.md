# Captured-attempt adapter assessment

This bounded [#194](https://github.com/VladimirMarko/conaled/issues/194) experiment connects captured source bytes with process evidence. A separate writer changes the live files while the adapter collects them; the child consumes private sealed files. Its small computation exercises source consumption without claiming that a real compiler consumed every dependency or building the repository. A later publication can take effect while its acknowledgment is lost. The implementation retains that uncertainty and refuses another launch.

The integrated model is [CapturedAttempt.lean](../../Applications/Interaction/CapturedAttempt.lean), with [checked cases](../../Examples/CapturedAttempt.lean) imported by the public umbrella. The [isolated adapter](../../experiments/captured-attempt/Main.lean) executes the model's capture and observation transitions. Its [public protocol and tests](../../experiments/captured-attempt/README.md) describe the supported Linux fixture. This is conditional refinement under explicit primitive assumptions, not a proof of Lean's IO extern implementations or production adoption.

## Reused contracts and remaining assumptions

`CaptureChain` has independent premises for each returned read, sealed write and child read. `capture_chain` composes them into the independent `CapturedExecution` contract; `captured_step` supplies the existing `Snapshot.CompileCaptured` relation. Arbitrary component types and history relations remain available. The two read histories need not be equal, and no coherent-revision conclusion follows.

The executable capture state admits reads and seals in order. `authorizeCaptured` exposes a launch only after both seals. The observer's `advance` delegates issuance to the existing Measurement controller, and each supported primitive response preserves the facts justified so far. `Evidence` includes an external witness for every observation step. Its correspondence theorem feeds the existing `successful_world`. These component facts alone do not connect capture, event ordering, physical invocation and an exact publication payload; `accepted_capture` is only a conjunction of separate component consequences. The joint prefix contract below supplies that connection.

`Joint.PhaseStep` independently specifies the allowed source steps. Its state retains read histories and values, sealed values, the authorized and actual child identities, consumed inputs, a single completion choice, actual exit/reap/channel facts, and the requested and selected publication payload. `Joint.next` is a separate target reducer over the same data representation. Sharing the carrier avoids a conversion layer; source legality is defined by `PhaseStep`, not by reducer acceptance or `Measurement.decide`.

`Joint.Admissible` checks the reducer and `Joint.Primitive` for each event in the same prefix. The primitive obligations are individual read admissibility, successful seal equality, child identity and each consumed component, supported exit, preservation of established exit facts during cleanup, reaping, finished channels, exact request encoding, and exact acknowledged payload. The events are normalized observations augmented by external witnesses. Actual exit/reap/publication-effect fields are such witnesses, not facts inferred from unknown observer knowledge. `encode` specifies the exact provisional serialization; proving the runtime JSON encoder implements it remains a runtime boundary.

`next_phase_refines` and `next_refines` derive a legal source step. `prefix_refines` constructs an allowed source prefix and related state for that same event list. `step_valid` and `prefix_valid` derive the retained facts from the empty initial state. `joint_success` then derives both consumers' contract: read/seal/child boundary equalities for the same child, exactly one actual spawn witness, normal zero, complete channels, reap, and acknowledgment of the exact selected provisional payload. `joint_measurement` projects those same source facts to the old Measurement world. Neither final correspondence nor joint success is a primitive assumption.

Authorization requires the sealed phase. A spawn consumes the authorized phase once; counting spawn events across an allowed prefix agrees with the source state's invocation count. Completion is selected once, before cleanup and channels. Cleanup can establish that the child exited and was reaped while preserving timeout or unknown as the selected completion. Requesting publication requires either collected channel observations or an aborted prefix. Aborted prefixes retain the preceding evidence and a fragment/effect witness, and cannot succeed. Publication and selection retain the exact requested snapshot; later pending or live-interference steps cannot replace it. Lost acknowledgment admits both effect/no-effect witnesses with identical observations and no second authorization.

| Boundary | Named premise | What remains unproved about the runtime |
| --- | --- | --- |
| Read | Returned bytes belong to the permitted read history; fixture barriers keep that file stable during its read | Kernel handle/read behavior and actual barrier observations. General concurrent reads need not be atomic snapshots. |
| Seal | Successful write/close exposes the recorded bytes; ownership preserves them | Filesystem visibility, absence of undeclared writers and symlink attacks. Failure may leave a prefix or full file. |
| Child input | Child reads the selected sealed paths and reports those read bytes honestly | Executable behavior of this trusted fixture. Hashes and exit zero alone would not establish consumption. |
| Wait | Returned raw zero means normal exit zero; successful wait identifies/reaps the owned child | Lean extern, libc and OS execution. The local installed runtime was inspected; nonzero values remain conservative. |
| Channels | Read prefixes, EOF and protocol checks refer to the owned files after the supported child terminates | IO and JSON/byte decoding adequacy. The model does not prove arbitrary subprocess output authenticity. |
| Publication | Successful write/close makes that exact provisional payload visible under private ownership | Durability, atomic replacement and acknowledgment delivery. Missing acknowledgment does not imply absence. |
| Frame | Established attempt facts survive permitted steps; live inputs may change | Arbitrary interference outside the ownership contract is unsupported. |

The compiled pure transitions and conditional theorems are checked Lean. The byte/JSON conversion, IO event production and barrier implementation are tested adapter code. The joint reducer is a checked protocol model; Main still uses the smaller capture and observation components. There is no proved normalization from every raw JSON/runtime event to the witnessed joint events, nor a refinement theorem for all executions of `Main.main` against an operational semantics of the OS. Fault injection supplies examples of the boundary relation, not exhaustive evidence that those assumptions always hold.

## Separating examples

The writer's stable observations are A0/B0, A1/B0 and A1/B1. Capturing A before the updates and B after them yields A0/B1. Checked Snapshot facts show why that pair is not a historical revision. The real child reports the sealed pair; a deliberately faulty path choice reports A1/B1 and is rejected even with exit zero.

Publication uses a provisional payload with unknown publication and false success. The acknowledgment-loss injection runs after a successful write/close. The supervisor sees the file; the returned selection stays unknown and the controller refuses another issue. A separate before-write injection has no file in that fixture. Both outcomes are compatible with conservative observer knowledge; no retry is inferred from silence.

The existing retained-measurement interpretation supplies the rollback case for this adapter's selected lost-acknowledgment response. No new exception algebra or recovery framework is introduced. The checked pending run shows that safety can coexist with indefinite noncompletion. Logical issuance counts are not time, memory or syscall bounds.

The review counterexamples exposed the missing joint connection in the original component statements. Those components remain useful with their narrower claims; the added protocol does not silently strengthen `advance` or `Evidence`. The checked concrete joint trace establishes satisfiability through all primitive premises and two source changes, and the negative cases demonstrate what the new ordering/payload obligations exclude.

## Runtime evidence and acceptance boundary

Development proceeded through public CLI red/green cycles with private retained artifacts. Cases exercise both source capture and benchmark-style process evidence: actual concurrent writer, exact consumed bytes, nonzero/signal, timeout boundary, missing/overflow/invalid outputs, real missing/oversized inputs, partial-read/seal injections, spawn-before-call, polling and cleanup uncertainty, publication before/after effects, truncated receipt, and preservation of existing evidence. Injections are labeled separately from requested faults and real observations. Every case checks at most one authorization; cases where the child reaches its marker check its unique marker. Early cleanup can prevent that marker without proving no spawn occurred.

Initial real smoke observations used roughly 1.83–1.85 GiB supervisor child-tree max RSS and 3.4–4.9 seconds per case. These include Lean loading the imported model and are not computation-child measurements or comparative benchmarks. The private test records retain exact source identities, commands, environment, raw observations and the metric's scope.

Exact frozen-candidate runtime results and independent review outcomes belong to the external implementation handoff. Integrated formal completion requires the repository's guarded fresh candidate build and proof audit, including the umbrella import. The isolated Main has separate typechecking/runtime evidence and is outside that audit's source inventory. No isolated proof-audit claim follows from a namespace name or from the integrated modules passing.

#43 verifier algorithms, #7 native parsing, #6 snapshot tooling, #195's shared Python runner and #423's recorder remain unchanged. The result informs a later adapter decision; it does not authorize Phase2 migration, general process management, crash durability, coherent revision capture or closure of every #194 obligation. Broad architecture adoption would need a separate decision backed by these remaining requirements.
