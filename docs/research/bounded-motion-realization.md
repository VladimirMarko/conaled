# Bounded motion realization

The second disk-motion executor uses the fixed-point arithmetic accepted in #538: scale 256, signed ticks in `[-65536,65536]`, floor-selected operations, and outward interval certificates. Its driver retains certificates for `Bounded.run`. The existing rational driver still certifies `Numerical.run` and retains its exact equivariance theorem.

The implementation is in [BoundedMotion](../../Applications/Orbifold/BoundedMotion/), with checked applications and executable comparisons in [Examples/BoundedMotion.lean](../../Examples/BoundedMotion.lean). The workload was frozen before integration at base `51160c785e523ba2881c74e508f3906d783231e6`.

## Executed arithmetic and error

Input conversion rejects coordinates, controls, errors, or durations that are outside the signed range or off the `1/256` grid. It does not round command time. Each accepted tick executes the existing position, frame, budget, and admission expression trees. The rounded output receives a separate integer domain check.

For output coordinate boxes with radii `r₁,…,r₄`, the local rounding allowance is `(r₁+r₂+r₃+r₄)/256`. `evaluate_roundoff` proves that this bounds the product norm of the actual selected state minus the exact Euler state. The stored error is the budget's upper endpoint plus those four radii. `checkedStep_correct` combines this allowance with the existing propagated input error and continuous truncation estimate. It proves both position/frame approximation to the continuous command endpoint and domain membership of the rounded output.

`checkedStep_mesh` and `run_mesh` provide a separate comparison with a successful rational Euler execution on the same mesh. Their recurrence multiplies the previous discrepancy by `1+13d` and adds actual rounding. It does not add the continuous truncation term. A comparison between different adaptively selected meshes must instead state which exact trajectory or mesh it uses.

Schedule success preserves every intermediate sample and the exact rational clock. Whole accepted intervals are committed; retries begin at the same incoming packet. On failure, the complete earlier event prefix remains in the report and the failing event remains pending. The event partition theorem retains the original C4 labels. Signed coordinate permutations implement relabeling exactly. Rounded execution is only approximately equivariant: conditional on successful executions in both representatives, `run_representative_bound` bounds the difference through the shared exact trajectory and both certified errors. It makes no promise that both searches choose the same subdivisions or have the same success status.

## Frozen workloads and separating cases

The primary arithmetic/performance packet has position `(1/8,-1/8)`, frame `(1/2,-1/4)`, and error `1/256`. It moves with control `(-1/2,1/4)` for `1/16`, relabels by one quarter turn, then turns at `1/2` for `1/64`. Both routes use the same event list, tolerances `1/4` and `1/2`, four search rounds, work fuel 128, and all four starting representatives. The rational route uses a 4096-bit packet guard.

The first bounded output retains the independent arithmetic oracle: position ticks `(29,-28)`, frame ticks `(128,-65)`, budget upper endpoint 41, and total coordinate radius 2. Its returned error is therefore 43 ticks. The selected budget value 40 would underestimate the exact budget and is never used as a conservative bound. The exact threshold 43/256 is accepted by a one-candidate search; 42/256 is rejected.

At tolerance `1/4`, starting representative zero, the bounded route commits the move and relabel, then rejects the turn. Its four turn candidates fail by accuracy, domain, domain, and precision respectively. The final committed clock is `1/16`, not the requested `5/64`. The rational route completes this word. The finer bounded schedules cannot silently round a duration below the grid. Conservative budget enclosures also need not improve monotonically as the mesh becomes finer.

The primary packet is an arithmetic fixture, not a claimed approximation to a valid Pose with error `1/256`: its frame norm is incompatible with that small error and the conformal frame scale. A separate exact origin Pose with frame `(1/2,0)` supplies the nonvacuous continuous-trajectory application. Its nonzero movement is proved through `checkedStep_correct`, with its incoming approximation premise discharged.

Retained cases cover empty and singleton prefixes, nonzero movement and turns, representative changes, the domain margin, insufficient tolerance, nongrid input, duration `1/512`, an out-of-range coordinate/control, work exhaustion, and a successful prefix followed by unsupported or unrepresentable input.

## Work, storage, and runtime

`startAccounted` and `rationalAccounted` expose the complete request-level source envelope described below. The earlier per-report vectors are diagnostics of the retained execution, not complete request costs.

The model distinguishes attempted ticks from reserved work. Every rejected schedule retains its attempted-tick count, including its failing tick. A candidate reserves its planned tick count plus one search decision; a relabel reserves one unit. Reservations can include a suffix that was never executed.

Arithmetic accounting charges all output and admission expression trees for every attempted tick. The expression traversal bound includes failing nodes and excludes unvisited right subtrees, so the full tree charge is conservative. Conversion, integer guards, search/schedule work, and retained packet writes are separate categories. A boxed arithmetic node is a model unit; it is not a machine instruction or a uniform cost in bits. Rational and bounded costs must not be ranked from attempted ticks alone. Rational normalization and integer allocation remain runtime concerns.

Each bounded scalar has an injective code with 131073 possibilities, fitting in 18 bits. Each packet stores five such scalars. The report's scalar-slot count includes its final packet, every observation's incoming packet, each command result and all samples, counting repeated occurrences without assuming allocator sharing. The implementation uses Lean `Int` and lists, not packed words. Retained rational command durations, labels, counters, errors in attempt logs, and list structure are reported separately from coordinate scalar codes. The common request (initial packet, event word, tolerance, limits, and fuel) remains the same explicit input to both measurements; the retained-report counts do not include that caller-owned request or transient allocation. Constructor tags and allocator headers are not assigned a bit layout. Rational comparison storage sums signed numerator and denominator bit lengths of the corresponding retained coordinate/error slots.

Runtime observations use the pinned Lean evaluator under the repository's direnv shell, one CPU, and the shared build lock. The emitted timings include rendering the result summaries and are separate from the modeled charges. They establish no speedup, allocator bound, or bit-operation theorem.

Metadata counts use signed numerator/denominator code lengths for rationals and binary lengths for natural counters. Scalar codes and metadata are mathematical encodings, not measured heap sizes. At the tighter tolerance the bounded route stores fewer packets because it returns an incomplete prefix, so that storage comparison does not describe equal completed work.

The bounded per-report diagnostic charges 513 expression nodes per attempted tick, including guard expressions even when execution stops earlier. For tolerance 1/4 its categories are 3591 expression nodes, 33 scalar input conversions, 30 scalar output observations, 294 integer guard/arithmetic units, 25 schedule/search units, and 5 retained packet writes. At tolerance 1/2 they are 1026, 13, 42, 84, 8, and 8. Input conversion includes the five initial scalars and four controls/time scalars per attempted tick. Integer units charge seven threshold comparisons, eight rounded-domain arithmetic/comparison operations, twelve radius operations, four error additions, four packing comparisons, and seven Boolean combinations per tick. The initial domain/error admission is one additional compound predicate unit. Relabeling costs two scalar negations per quarter turn, hence two for this word. Initial representative conversion is common workload setup outside the driver counts.

The matched rational per-report diagnostic charges 1026 formula-tree nodes, 20 packet-scalar bit scans, 5 setup copies, 42 output scalar observations, 8 schedule/search units, 8 retained packet writes, and 2 relabel negations. A rational formula node includes exact normalization as one model operation. Formula-tree envelopes and compound scheduling units deliberately avoid a host instruction or bit-operation model. Output observations account for reading all retained scalar slots and attempt errors; they need not all be materialized by the driver. The vector reports these categories separately, so it cannot be read as a sum of interchangeable time units. The formal work theorem bounds actual attempted ticks by reserved fuel; the expression theorem bounds visited nodes by full trees. These diagnostic categories are declared executable accounting functions, not a proved machine-level resource bound. The request-level envelope supplies the missing setup and rejection coverage.

The tools are Lean 4.35.0 and the repository's pinned Lake dependencies and Nix flake. To reproduce the smoke cases and emitted observations after building dependencies, run from the checkout:

```sh
direnv exec . lake build Examples.BoundedMotion
direnv exec . lake env lean Examples/BoundedMotion.lean
```

For the recorded development measurement, execution was serialized with `flock` and pinned with `taskset -c 0`, at `nice -n 10`. Eight bounded runs including rendering took 0.562–4.344 milliseconds; eight rational runs took 0.124–0.344 milliseconds. These are individual observations from the successful focused build, not repeated benchmarks or confidence intervals. Compilation, external process startup, and dependency builds are outside these timers. Rendering, garbage collection, and scheduling noise can dominate these small workloads.

## Complete request-level source envelope

The complete accounting boundary begins with the rational input packet and configured request, before bounded conversion, and ends with traversal of the retained result. `startAccounted` returns both the original `Except` result and a conservative envelope, including when initial conversion or admission rejects. Its erasure theorem recovers `start` exactly. `rationalAccounted` has the same boundary and erases to the unchanged rational `drive`.

The source model uses named compound operations. An initial scalar slot performs one complete conversion or rational copy, including representation checks. Two initial predicate slots reserve admission and failure classification, even if either is skipped. An event slot includes pattern dispatch, support/fuel checks, recursive return, clock/counter updates, and result construction. Each candidate cell includes range/map construction, exponentiation `2^k-1`, and storage. Each candidate-check slot includes the reservation/accuracy decision and its attempt-log construction. A schedule slot includes exact subtick duration division, list construction and traversal. A step slot includes all conversions, AST operations, guard evaluation, packet-size checks where applicable, error/sample construction, and arithmetic needed by that attempt. A quarter-turn slot performs the complete signed coordinate permutation. Output scalar slots cover retained packet coordinates/errors. An output list-cell slot includes traversal and handling its metadata payload (event controls, attempt outcomes/errors, labels and counters). Together they cover the complete retained result. These compound units deliberately have different computational contents; their counts are reported as a vector, never summed into a time estimate.

For `n` input events, `r` configured rounds and fuel `f`, the request envelope reserves 5 initial scalar slots, 2 initial predicates, `n+1` event slots, `r*n` candidate cells, `(r+1)*n` candidate checks, `f` schedule slots, `f` step slots and `3*n` quarter turns. The original request, rather than a successful report alone, determines these charges. Reserving even unreachable events and unconsumed fuel makes this conservative; it is not an exact trace. Initial failure still receives this envelope and zero output slots. The rational route reserves the same setup slots even though it needs no conversion rejection predicate.

The coverage proofs connect these reservations to the actual drivers. `drive_searches_le` bounds actual search invocations by input events. `candidate_cells` proves the eager candidate list length is the configured round count. `search_attempts_le` bounds search iterations by that list; one additional check per search covers exhaustion or refusal. `search_planned_le` and `drive_planned_le` bound the full allocated schedules, including their unexecuted suffixes, by reserved work, which `drive_work` bounds by fuel. Actual attempted steps are also bounded by fuel. Reserving a step slot for every planned schedule position covers a rational packet-bit rejection before the measured tick counter increments. Prefix partition bounds committed observations; one additional event slot covers the failing dispatch or terminating return. `relabelTurns_le` bounds C4 relabeling by three turns per event. The five source positions in `importPacket` and its short-circuiting bind chain justify the five reserved conversion slots; both possible post-conversion paths fit the two predicate slots. Complete-output counts are extracted from the very result returned by the erased wrapper, not from a substitute execution. The existing AST visit theorem provides finer accounting inside a step slot. No part of this coverage asserts a machine-instruction, bit-operation, allocator or elapsed-time bound.

For every frozen run, `n=3`, `r=4`, and `f=128`, so both routes reserve the source vector `(5,2,4,12,15,128,128,9)` before output traversal. The bounded tighter-tolerance result adds 25 scalar slots and 11 list cells; its looser result adds 40 and 9. Rational results add 40 and 9 for either tolerance. These conservative request vectors are identical where the request is identical; the earlier diagnostics explain differing actual attempts and retained prefixes.

Three executable separating cases guard this boundary. A one-command first-candidate success with one versus four configured rounds retains identical returned packets and one attempted tick, but charges one versus four candidate cells. The same command with fuel one rejects before any attempted tick while retaining four candidate cells. A nongrid initial coordinate rejects with precision failure while retaining all five conversion slots and both predicate slots, and no output traversal. These checks exercise the cost-bearing wrappers themselves.
