# Measured callbacks: implementation and use assessment

Recommendation: retain `Resources.Measured`, `run`, the exact append executor, and the existing uniform-price list operations. Trial a small ordered measured-map operation and explicitly chosen concat composition against the counter-output and permutation clients. The present evidence does not justify a broader observation interface. This is an assessment, not authorization to adopt it.

The strongest retention evidence is already executable mathematics: `BinaryCounter.advanceWithCost` delegates to `run`, and `advanceWithCost_eq` proves equality of the complete measured pair for arbitrary bit lists. `Measured.bind` combines observations in sequence without commutativity. `ListAppend.weighted_exact` retains both output and actual copied-left-spine work. The requested capability extends these owners naturally; it does not expose a defect in their stated contracts.

## Where builders and callers spend effort

With local recursion, each builder repeats nil/cons equations, callback value projection, callback observation accumulation, ordered output reconstruction, and induction for the exact pair. Concat callers additionally repeat append accounting over actual callback results. A shared measured-map owner can absorb these obligations once. Callers should supply only the callback and its domain-specific specification, then derive their specialized formula from actual callback bills.

Using `run` directly is a viable alternative. It already sequences varying measurements and supports invariants. A list-producing caller must choose an accumulator representation and prove the output order, however. Consing into an accumulator reverses the result; reversing afterward adds a source operation if that is the declared implementation. Repeatedly appending singleton results changes the copied-spine bill. Difference lists instead introduce an arbitrary-tail correctness obligation. These are concrete costs of encoding a map through a state runner, not mathematical inadequacy of `run`.

Measured permutation recursion adds one obligation that a plain map should not hide: Lean's termination argument uses membership proofs from `picks.attach`. `bySelection` explicitly uses `picks_remainder_length`. A traversal over attached occurrences, followed by a theorem forgetting attachments, is sufficient in principle; the author trial must check that it does not duplicate termination adapters at every recursive call. Do not add dependent machinery before this trial reveals a need.

Counter callers must keep transition measurement separate from rendering states. Rendering five states does not authorize five increments. `[]` and `[false]` have the same numeric value but different token lengths, so a renderer cost theorem should not quotient representations by `value` without a separate invariance proof. No canonicality restriction is needed merely to traverse the actual states.

## Order and observation boundaries

There is a genuine scope risk if a new generic traversal is inferred from existing scalar fusion equations. `ListFusion.map` has no measured callback and accumulates scalar costs after the tail. It establishes no callback-event trace order. Likewise, `concatMap` executes a map phase followed by a concatenation phase. An interleaved map-and-append implementation can have equal values and equal natural-number work while differing in an ordered event observation.

An especially useful separator is map fusion: two complete maps produce callback events `g(a), g(b), f(g(a)), f(g(b))`, while a fused map produces `g(a), f(g(a)), g(b), f(g(b))`. Existing `map_fusion_saving` is a scalar source-cost theorem and remains valid. A proposed generic full-observation fusion theorem would need a different statement or additional commutation premises. This is a paper counterexample to the stronger proposed theorem, not a defect in the existing theorem.

Construction and forcing need separate operations. `Applications/Resources/CollapseMaterialization.lean` already supplies a useful concrete precedent: `SumThunk`, `sumMapStep`, and `labelStep` construct delayed labels, while `buildAux` invokes the selected thunk and adds its work. Its `BuildRun` retains distinct measurement components. There is no reason to replace that demand protocol with a total list traversal.

A list of `Unit → Measured β C` can be traversed to count outer cells without invoking its callbacks. A full observer must invoke each thunk, retain each returned value, and charge any requested inner-spine observation. Empty inner lists still incur the inner observer's terminal charge. Repeating the observer repeats the measured bills; function values provide no cache transition. The recovered target `flatten.length + 3 * outer.length + 1` is tied to its proposed complete-observer model. It is not the existing `concat1_work` formula, which is `2 * flatten.length + 2 * outer.length + 1` and charges copying through append.

## Smallest useful alternative and acceptance cases

Start with a small ordered map whose callback has type `α → Measured β C`. Declare the exact order of callback and structural events in its recurrence. The generic operation needs only the operations it uses; add monoid assumptions to composition/transport theorems as required. Supply exact nil/cons equations, value erasure, observation recurrence, and additive reweight transport. These are derived theorems, not new callback proof fields. Offer a `Nat` structural-price specialization. Retain the old uniform map and prove complete pair equality for constant-cost callbacks under that specialization.

For concatMap, first reuse measured map followed by the existing measured append-based concatenation for the scalar model. If ordered append traces are required, explicitly implement the corresponding trace-producing append traversal; the scalar bill cannot reconstruct those events. An interleaved concatMap is also admissible, but should have its own source equation and not claim exact trace equality to the two-phase pipeline.

The following are proposed independent fixtures, with hand-computed expectations, not executed Lean tests:

1. Counter rendering: render the actual five states `bits 5`, with each line callback returning its tokens and billing `state.length + 1`. The state lengths are `0, 1, 2, 2, 3`; callback bills are `1, 2, 3, 3, 4`. With dispatch and produced-cell price one, a direct measured map should retain all five token lines and bill `13 + 11 = 24`. Separately test `[[], [false], []]`: all decode to zero, but the line bills are `1, 2, 1`, totaling `11` with map overhead. This tests duplicate occurrences without requiring duplicate states from an increasing counter.
2. Permutation output: traverse `bySelection [1,1,2]` with an output callback retaining each list and charging one plus its head value. Exact order is `[[1,1,2],[1,2,1],[1,1,2],[1,2,1],[2,1,1],[2,1,1]]`; bills are `2,2,2,2,3,3`. With the same map overhead the total is `14 + 13 = 27`. Tag occurrences externally for the trace so deduplication and reordering cannot pass accidentally. This tests an output consumer; a separate recursive executor test must cover selection/removal and append charges.
3. Delayed payloads: construct thunks for `[[], [a], [], [b,c]]`. Outer counting must leave the callback trace empty. Complete observation must retain all four payloads, including empty ones; the recovered complete-observer target gives `3 + 3*4 + 1 = 16` before any separately declared thunk bills. Force one nonzero-cost thunk twice and expect two charges.
4. Composition: use noncommutative callback-event lists together with scalar bills, and compare exact pairs for a two-phase and interleaved pipeline. Retain the distinct traces even where scalar totals agree. Include function-valued payloads to ensure traversal itself adds no `DecidableEq` assumption.

Compare these consumers implemented locally with those using the small owner. Record required inductions, termination adapters, and reusable lemmas, rather than judging only line count. Keeping local traversals plus shared bind/fold lemmas remains a defensible outcome if the owner adds wrappers without removing recurring obligations.
