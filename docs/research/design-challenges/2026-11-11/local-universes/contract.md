# Contract and foundations assessment

Retain both weak-unit constructions and the Type-family baseline. The current evidence supports a small second-constructor comparison before extracting a shared representation interface. It does not establish that a broader local-universes interpretation strategy would save work. The strongest retention evidence is the combination of whole-functor representation inverses, naming naturality, exact agreement for the same supplied lifts, and arrow-sensitive counterexamples. None of those observations should be weakened to obtain a cheaper interface.

## Derived laws and supplied data

In `Applications/LocalUniverses/WeakUnit.lean`, `Lift` supplies an actual target, equality of its image with the requested object, and an isomorphism from the original object. `NormalizedLifts` additionally supplies lifts for all outgoing arrows, their image equation, and identity normalization. It has no composition law. `direct` builds arrows by `conjugate`; cancellation of endpoint isomorphisms supplies functoriality. `direct_projection` consumes `image`, the branch equation on arrows (`branch_map`), and naturality of the codiscrete leg. `direct_substitution` derives equality of complete functors from the fixed lift function and `selected_substitution`. Composite substitution then follows by applying that theorem to a composite functor. Adding final stability or split-composition proof fields would duplicate a derived guarantee or impose a stronger independent requirement.

There is one concrete excess assumption worth recording: `NormalizedLifts.identity` is not used by the construction or its proofs. `directIso` explicitly chooses `Iso.refl` at zero, and only the other endpoint invokes the supplied lift. Identity normalization is therefore stronger than the actual requirements of these definitions. It does not follow from the lift/image data: in the C2 projection, a nonidentity vertical automorphism over an identity base arrow can serve as its chosen lift. That gives an image-correct choice failing normalization. This separation is a paper countermodel using the existing C2 data, not an executed new example. Removing normalization from the minimal input would weaken an existing requirement, rather than change the operations or add a new law. Keeping the normalized wrapper for the documented comparison is harmless; a future shared constructor API should not accidentally inherit normalization as a necessary hypothesis.

`Parameter`, `Parameter.Hom`, `name`, `realize`, and `representation` retain strict branch equations and all natural-transformation components. `Parameter.functor_ext` requires both motive and branch projections. `realize_represent` and `represent_realize` prove inverses on actual native data and whole naming functors. `name_substitution` supplies the naturality needed to derive `parameter_substitution` by composition with one fixed generic filler. The parameter route could accept an independently supplied generic filler plus beta/projection proofs; stability would still follow. Existence of that filler would then remain a separate obligation. Currently `generic` constructs it by `direct`, so the existing route is not an independent existence theorem.

`instantiated_agreement` depends on that specific construction of `generic` from the same lifts. Equality for unrelated generic choices is unavailable. In `Examples/WeakGroupoidUnit.lean`, `distinct_fillers`, `same_branch`, and `filler_over` exhibit equal branch/projection behavior with unequal functors. `swaps`, `fixes_whole_branch`, and `swap_over` show why equivariance under all presentation automorphisms is a stronger requirement than context substitution. `fails_composition` separates normalized lifts from split lifts; `repaired_roundtrip` and `retains_branch_arrow` show that conjugation repairs the former without deleting branch arrows.

## Foundations actually used

The checked weak-unit theorem assumes groupoids Γ, E, V and arbitrary substitution functors, an E-to-V functor with supplied lifting data, and an exact functor equation for its branch. It explicitly constructs products, the functor-category motive, the strict parameter category, evaluation, currying and their equations. It does not take LF, a comprehension category, a universe classifier, or a global choice of lifts as inputs. Nor does it construct those foundations. Its universe parameters permit the ambient Lean types needed by this bounded construction; this is not a proof of a Grothendieck-universe model theorem.

The direct argument itself appears to require only categories for the context and codomain, together with the supplied endpoint isomorphisms, rather than inverses for every ambient arrow. The groupoid instance for `Parameter` does use groupoid inverses. Generalizing these signatures would require a checked trial: it is an opportunity to separate assumptions, not an established drop-in replacement.

`SquareKit/LocalUniverses.lean` works in already split native Type families. `Family.reindex_id`, `reindex_comp`, `decode_reindex`, and `sigma_reindex` reduce directly. `comprehensionEquiv` constructs the pairing universal property for arbitrary functions. `displayCurry` and `displayCurry_natural` construct the stated section bijection and its naturality. They are useful concrete evidence; they do not by themselves implement arbitrary full comprehension categories or all LF exponentials. The explicit `Examples/LocalUniversesBoundary.MissingTerminal.no_terminal` counterexample prevents deriving even a terminal context from the current source `Model` interface alone.

The supplied research documents identify an ambient Lumsdaine–Warren theorem. I have not independently inspected its primary source in this assessment, so I do not certify that theorem's hypotheses or its groupoid specialization here. Any recommendation to instantiate that general theorem must separately verify full comprehension on all intended morphisms, the required dependent exponentials and finite products, weak stability for the selected constructors, and universe/choice closure. Those obligations cannot be replaced by the bounded weak-unit proof or inferred from the source `Model` record.

## Concrete next comparison: dependent functions in Type families

A small additional constructor is Π on `Family`. The existing `Family.sigma` already uses the parameter type

`(a : A.Parameters) × (A.fiber a → B.Parameters)`.

The same parameter type and naming map can support a proposed Π family whose fiber at `(a,b)` is `(x : A.fiber a) → B.fiber (b x)`. Decoding should recover `DependentSquares.piTy`; strict substitution should follow by the same explicit naming calculation as Σ. Lambda and application can reuse `DependentSquares.lam`, `app`, `lam_subst`, and `app_subst` in `Dependent.lean`. This is a proposed construction, not a claim it is currently implemented.

The direct comparator already exists: `piTy`, `pi_subst`, lambda/application and beta/eta are defined in native families. Thus this trial would measure reuse of the parameter shape and dependent name map, not prove that strictification is necessary in Type. It needs native dependent sums/functions closed at the existing universe, explicit comprehension, and pointwise function equality. It needs no isofibration choices, groupoid inverses, classifier, or ambient LF theorem. Moving that exact construction to an arbitrary category would introduce representation/exponential obligations that native Type already provides.

The smallest useful extraction, if the trial succeeds, is the dependent input parameter object and its naming/substitution helper shared by Σ and Π. Do not merge Type-family and weak-groupoid-unit representations merely because both are called parameters: their input shapes and semantics differ.

Discriminating tests should cover dependent `Fin` tails already used by `Examples.LocalUniverses.DependentTail`, lambda/application after the existing `shift` and `double` substitutions, and an empty domain fiber. Require decoded agreement with the existing direct Π operations, both substitution steps, and beta behavior. Compare actual repeated proof obligations before and after the helper. A second constructor with nonunique fillers remains needed to test whether generic selection itself pays for its representation setup; the Type Π trial cannot answer that question.
