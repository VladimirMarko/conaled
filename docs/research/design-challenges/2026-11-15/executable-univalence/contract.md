## The endpoint contract already has a useful narrow boundary

`SquareKit/Internal/Cubical/UnivalenceTransport.lean:162` defines actual transport by `IntervalTransport.mapTo` on the decoded `uaCode` family's chosen filling, with decoder endpoint equalities. Its `comparison` at line 169 is a native path from the supplied map to that transport. This is the correct semantic target, rather than a new function named transport.

`Examples/CubicalUnivalenceTransport.lean` already supplies the complete observation bridge for ordinary equivalences: `codeIso`, `input`, `codeTransport`, `observed`, `observed_eq`, and `value_eq`. `observed_eq` maps the native comparison through the target decoder and uses `discretePath_endpoints`; `value_eq` observes at the terminal point. Thus the executable candidate `e s` has an existing semantic target and proof route. Boolean negation and a finite cycle can use that route without reconstructing native evaluation.

This theorem uses the selected witness `HomotopyEquivalence.ofIso (codeIso e)`. That is a legitimate bounded admission rule, but should appear in the frozen contract. It must not be presented as execution of arbitrary supplied native equivalence witnesses. A stronger adapter may accept arbitrary `f,E` plus executable forward/inverse implementations and proofs identifying their observations with those of `f`; this separates executable data from native witness data. The existing #530 package route deliberately retains the exact supplied `E`, so the stronger option should not replace it silently by an `ofIso` witness.

For repeated/inverse changes use `NativeUnivalence.compositeTransportComparison` in `CompositionalUnivalence.lean:99` and actual reversed-path transport (`reverseTransportLeft`, `reverseTransportRight`, `inverseMap`). Sequential execution of two maps agreeing with a newly constructed composed map is insufficient evidence for the actual concatenated endpoint. Likewise applying `value_eq` to `e.symm` alone establishes a newly constructed inverse ua endpoint; relating it to reversal of the original path needs the #528 comparison. These obligations are present for either direct execution or syntax.

## Whole package recovery is available, with explicit scope

`Examples/CubicalStructuredState.lean:282-330` defines source and target readouts through actual `admittedStart`/`admittedFinish` decoder isomorphisms. `sourcePackage_eq` recovers the source package. `targetPackage_eq` identifies the target of the selected package filler with `p.conjugate (admittedCarrier f E)`. `transported_recovery` concerns the entire native section. Therefore #533 need not settle for two new surrogate state machines.

Use the finite client already in `Examples/CubicalFiniteStateIdentity.lean`: `machine : StatePackage (Fin 3)`, `presentation : Fin 3 ≃ Phase`, `presentedMachine`, and `observer`. `machineTransported_eq` connects the actual package endpoint to the executable conjugate; `transported_observation` and `transported_invariant` provide initial calibration. Extend from the one-step observation to the selected workload using the transition equation and `Resources.run_value_fusion`/`run_invariant`, while retaining all package fields in the semantic theorem. Specify whether observations occur after every transition or only at the end: costs differ even when final states agree.

The selected package includes the initial state, transition, invariant predicate, initial proof and preservation proof (`CubicalStateTransport.lean:12`). The invariant is a proposition-valued function, not automatically an executable Boolean test. If runtime invariant checks are desired, supply a decidable Boolean observer and prove its relationship to that predicate; charge its execution. Merely retaining `invariant : S → Prop` is a semantic guarantee, not a runtime check.

This exact whole-package recovery relies on the documented discrete PLift proof fragment. `package_ext` in `CubicalStatePackageFamily.lean` uses pointwise proof subsingletonhood, and `readOut_injective` in `CubicalStructuredState.lean` additionally recovers Pi values at all substitutions. Runtime result equality alone does not prove preservation of arbitrary native identity witnesses. Do not generalize the selected fragment to proof-relevant native fields without a replacement argument.

The existing negative control is strong: `wrongPresentation` preserves the selected initial point but violates the first transition, and `wrong_path_rejected` rules out the corresponding structured path. Retain it alongside the new executable observations. It detects an error that equality of carrier size or initial state cannot.

## Choice and erasure boundary

The inspected native semantic route is noncomputable (`codeTransport`, `ua`, `transport`, package line/presentation and target readouts). The report `cubical-glue-univalence.md` records audited dependencies `propext`, `Classical.choice`, and `Quot.sound`; I did not rerun that audit. #533 should audit its actual selected declarations and transitive dependencies rather than repeating the older report as a new result.

Noncomputable annotation alone does not identify the use of choice. For example, `HomotopyEquivalence.discreteInverse` (`DiscreteEquivalences.lean:114`) extracts the supplied generic fiber center; it does not search for a finite inverse. The enclosing `discreteIso` is noncomputable, and the semantic terms it consumes remain outside the executable route. This is a reason to accept explicitly supplied executable maps, not infer executable extraction from finiteness or an existence theorem.

Keep the runtime carrier, maps, transitions and numeric/Boolean observers explicit and computable. Put the relation to native semantic values in correctness proofs. Preserve the supplied native witness on the proof side where the theorem quantifies over it. Do not erase forward versus inverse maps or identify distinct native paths because their proof certificates are absent from the executable artifact. State separately the checked Lean equality, the chosen execution mechanism for the computable functions, compiler/runtime trust, and modeled source event accounting. The acceptance proof audit is necessary but is not compiler correctness or timing validation. If exact compiler erasure claims are made, check the pinned toolchain's implementation/documentation; no such new compiler claim was verified in this assessment.

## Costs and the alternatives

`Applications/Resources/Measured.lean` already has `bind`, `bind_erases`, `erasureSquare`, and `same_value_different_cost`. `Workload.lean` executes ordered commands and proves exact event recurrence and state fusion. `Prepared.lean` separates preparation, answer, storage, bounds and maintenance; its maintenance validity relates retained state to the *new* static input. These APIs can express this task without a new generic resource layer.

For an explicit target transition `e (step (e.symm t))`, record the inverse conversion, source transition and forward conversion in execution order. Include initial conversion/setup and every observer invocation. A proposed constant-tariff unretained run with n steps and n observations costs `setup + forward_initial + n*(inverse + step + forward + observe)`, plus any requested final conversion. This is a design formula, not a checked bound; it applies only when those are exactly the chosen executed events and tariffs are constant. State-dependent tariffs instead use the existing recurrence. Count a zero-use run's actual setup policy, including eager setup if performed. Do not cancel conversion events merely because their values cancel.

The existing parser short-workload rejection and representation cost report already show why preparation does not imply improvement. Reuse those controls; add only the finite fragment's particular calculations. If a retained source representation avoids round trips, specify the retained state, observable decode, allowed updates and rebuilding/invalidation work. Storage needs an explicit declared cell interpretation. With no retained optimization, document that choice and avoid inventing storage or invalidation machinery.

The direct adapter has the strongest evidence: supplied ordinary equivalences and conjugation already exist, and their native endpoints have comparison theorems. It preserves ordinary callers and makes the executability boundary small.

The small syntax remains viable when a client needs to inspect composition, normalize paths of representation changes, serialize a finite plan, or reuse a prepared plan. Its value would be the extra operation it supports. Semantic cancellation supports only observation preservation, and does not establish cost equality. A cost-reducing normalizer must specify the executed residual plan and charge normalization/setup. Do not require all existing direct callers to construct syntax.

A broader evaluator remains a long-term option if the intended client consumes native expressions beyond supplied finite equivalences, or requires source reduction rather than observed execution. It would need an admission boundary, reduction strategy, operational correctness/termination obligations and cost interpretation. None follows from the present noncomputable model or the finite examples. Rejecting it for this issue is a scope decision, not a mathematical impossibility claim.

## Established concerns, risks, and a discriminating experiment

Established by inspected interfaces: the comparison is a native path before the discrete decoder observation; inverse ua and reversed original ua are separate endpoints; the package invariant is not a runtime Boolean; the semantic package carries dependent proofs; event costs and storage have separate contracts. These are obligations for the implementation, not defects in the existing design.

Plausible implementation risks: accidentally replacing exact `E`; calling noncomputable readout code at runtime; testing only an involution; accepting initial-point preservation as operation preservation; proving a value theorem while omitting observer or setup costs. No implementation was supplied here, so none is reported as an observed implementation bug.

The smallest useful experiment is one module with executable Boolean negation, a `Fin 3` cycle and its inverse, and the existing finite package adapter, all connected to the actual native endpoint theorems. At state 0 the cycle and its inverse should yield distinct states (1 and 2). Include a noncommuting finite permutation pair to detect composition-order mistakes; inverse cancellation alone can hide them. Execute zero, one and repeated transition/observation workloads, check exact declared costs, and show the wrong presentation fails the package contract. Prove workload observations against `machineTransported`, not only `presentedMachine`.

Compare a tiny syntax executor only on the same workload, with the same observation points and complete setup costs. Choose syntax if a demonstrated normalization/reuse capability improves that workload or author obligation enough to justify its interpretation theorem. If direct composition and existing workload APIs already express everything, retain the adapter and record the syntax comparison without adopting it.

Missing evidence before completion: the precise frozen event tariff and runtime model; actual executable functions and tests; selected declaration dependency audit; checked bridge for actual concatenated/reversed endpoints; whole-package workload proofs; any retained-state validity/storage/invalidation theorem; and independent acceptance checks. No universal evaluator, source conversion, arbitrary proof-field erasure, wall-time improvement, or Wasm conclusion is supported here.
