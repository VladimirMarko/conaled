## Shared owners and meanings

The ordinary carrier is Mathlib's `BinaryTree α`: nil is an external empty leaf,
and a node stores a label with two children. Node count, external-leaf count,
maximum height and the generated structural recursion retain their standard
meanings. Informal root, spine and depth terminology adds no separate graph
formalism. Postorder is expressly omitted by the source chapter.

The [observation owner](../../Applications/Trees/Observations.lean) provides the
canonical fold and inorder. Independent set/preorder/structural-subtree laws
live in [BasicObservations](../../Applications/Trees/BasicObservations.lean).
[Shape](../../Applications/Trees/Shape.lean) owns minimum height, completeness,
almost completeness, discrete bounds and logarithms;
[ShapeLog](../../Applications/Trees/ShapeLog.lean) connects those to the source's
real logarithms. Complete means perfect, including nil. Almost complete means
external leaves lie on two adjacent levels, without a left-packing requirement.

The chapter's [traversal exercises](fdsa-tree-traversal-exercises.md),
[consuming balance](fdsa-tree-balancing.md),
[completeness and maximal-subtree development](fdsa-tree-completeness.md),
[generic cache](fdsa-tree-cache.md), and
[raw maximum cache](fdsa-tree-maximum-cache.md) retain their detailed statement
and execution explanations. The row map below gives their actual contracts and
the shared structural witnesses together, rather than treating module presence
as coverage.

## Source corrections and operational restrictions

1. **Sorted input and strict search trees (FDSA-4-58).** The strict BST
   interpretation requires strictly increasing inorder. The checked ordinary
   and keyed correspondences retain their Preorder assumptions on the compared
   labels or keys. Repeated sorted keys remain
   valid balancer inputs but cannot satisfy strict root/subtree ordering. The
   source figure and repeated-key counterexample retain that distinction.
2. **Undersized balancing input (FDSA-4-48).** The actual core returns `Option`
   and succeeds exactly on the stated length domain. Source-compatible useful
   contracts keep that domain; no label inhabitant is silently introduced to
   manufacture a missing node. Full-list/full-tree wrappers are total on their
   own naturally sufficient input sizes.
3. **Balancing wrapper costs (FDSA-4-18, FDSA-4-61).** The linear consuming core
   follows the suffix returned by its first recursive call. Literal direct
   inorder, the suffix-accumulator path and construction-inclusive staging
   have separate measured composition theorems. Their equal returned values
   do not identify their costs.
4. **Quadratic traversal is worst-case (FDSA-4-18).** A left-chain family attains
   the triangular append-work bound; a right chain has a different, linear
   count. Cost theorems retain the actual append association and stated
   primitive tariff, rather than claiming quadratic work for every tree.
5. **Almost-complete constructor law (FDSA-4-59 to FDSA-4-60).** Almost-complete children
   with heights differing by at most one are insufficient. If the heights
   differ, the shorter child must be complete. The exact iff and a checked
   counterexample to the weaker rule are both retained.
6. **Maximum annotation type (FDSA-4-75 to FDSA-4-76).** Raw node annotations have the
   label type α and the empty reader result has type `Option α`. Explicit
   adapters connect that source representation to the generic optional cache.
   There is no invented bottom value; validity is sufficient, not necessary,
   for the reverse adapter's round trip.
7. **Algorithm restrictions are part of the obligation.** The accumulator
   uses cons and invokes its suffix function without append; `levels` makes
   one input-tree fold without depth arithmetic or repeated depth queries;
   maximal-subtree selection uses child summaries without a separate
   completeness call, subtree enumeration or tree-equality test. Extensional
   agreement alone would not establish these restrictions or resource claims.

## Observations, costs and interoperability

Inorder and key erasure preserve sequence order and multiplicity. Set and
maximum observations deliberately forget some of that information. Label maps
are arbitrary, and raw structural laws keep independent universes and empty
label types wherever their meanings permit them. Reconstruction's decidable
equality and distinctness assumptions belong to that algorithm and its inverse
contract, rather than to every tree operation.

The consuming balancer, cache adapters and measured clients compose existing
conaled APIs. Canonical inorder connects ordinary and keyed search-tree
observations; the shared set interface and relational squares connect actual
implementations and operation sequences. Generic folds and fusion supply cache,
product and ordered-summary meanings. Independent shape and set observations
remain specifications for these algorithms.

Every cost claim states its observation. Structural call counts, copied-list
work, suffix invocation, local cached access and callback charges are distinct.
The generic cache node has callback cost plus three local-access/entry charges;
its size and height examples explicitly inline arithmetic at zero callback
charge in that source model. An actual append callback remains size-dependent
even on valid cached inputs. If each of the size callback's two additions costs
one, the value-correct callback has charge two and the same generic node law gives
cost five. The corresponding max-and-successor height tariff also gives five.
The chapter audit input retains explicit value/cost/validity instances for both
choices; these are instances of the shared theorem, with the primitive-cost
assumption stated separately from the inlined-arithmetic model.
No equality of tree values proves allocation,
physical sharing, bit complexity or machine time.
